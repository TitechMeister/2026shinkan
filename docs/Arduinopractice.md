## はじめに

このテキストでは、主に「XIAO RP2040」というマイコンボードを用いたプログラミングの基礎を解説します。
XIAO SAMD21を使う場合も、この教材で扱うLED、ボタン、アナログ入力、PWM入力、UART、I2Cの演習は同じ考え方で進められます。ただし、Arduino IDEの初期設定や書き込みに失敗したときの操作はRP2040とSAMD21で異なるため、各所にSAMD21向けの補足を入れています。
各レッスンは、「コード例」→「用語の解説」→「プログラムの動作」の順で進みます。最初にサンプルコードを実行してどのような挙動をするのかを教材を読みながら理解してください。最後に演習問題を用意しているので、実際に手を動かして理解を深めましょう。

### この教材でできるようになること

この教材を終えるころには、単にサンプルコードを写すだけでなく、人力飛行機に載せるセンサ基板を開発するときに必要になる基本動作を、自分で読み解けるようになることを目指します。

- LEDを点灯・点滅させ、マイコンから外部部品を制御する
- ボタンの入力を読み取り、押された回数や状態をプログラムで扱う
- 超音波センサから距離データを読み取り、単位変換して表示する
- 温湿度センサとI2C通信を行い、データシートの値を実際の温度・湿度に変換する
- センサ値の平均を取り、ノイズで値がふらつく問題を小さくする
- `delay()` で処理を止めずに、複数の処理を同時に進める考え方を身につける
- 関数、構造体、クラスを使って、センサ処理を再利用しやすい形に整理する

人力飛行機では、飛行中に複数のセンサを同時に読み続けたり、取得した値を後から解析したりする場面があります。そのため、この教材では「LEDが光ったら終わり」ではなく、センサ開発につながる考え方まで少しずつ扱います。

### Arduino IDEの初期設定

XIAO RP2040またはXIAO SAMD21にプログラムを書き込むには、最初にArduino IDEでボードの設定を行う必要があります。
この設定は最初に一度行えばよく、以降はボードとポートを選んでプログラムを書き込めるようになります。

#### 1. Arduino IDEをインストールする

PCにArduino IDEが入っていない場合は、Arduino公式サイトからインストールしてください。
インストール後、Arduino IDEを起動します。

#### 2. ボードマネージャのURLを追加する

Arduino IDEのメニューから、**ファイル > 基本設定** を開きます。
「追加のボードマネージャのURL」に、使用するボードに対応するURLを追加してください。

XIAO RP2040を使う場合：

```text
https://github.com/earlephilhower/arduino-pico/releases/download/global/package_rp2040_index.json
```

XIAO SAMD21を使う場合：

```text
https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json
```

すでに別のURLが入っている場合は、右側のボタンを押して一覧を開き、改行して必要なURLを追加します。RP2040とSAMD21の両方を使う可能性がある場合は、2つとも追加して構いません。

#### 3. 使用するボード用のボードパッケージをインストールする

Arduino IDEのメニューから、**ツール > ボード > ボードマネージャ** を開きます。

XIAO RP2040を使う場合は、検索欄に `RP2040` と入力し、**Raspberry Pi Pico/RP2040** というボードパッケージをインストールしてください。

注意：
`Seeed XIAO RP2040` という名前の古いボードパッケージが表示される場合がありますが、この教材では使用しません。
`Raspberry Pi Pico/RP2040` パッケージに含まれている `Seeed Studio XIAO RP2040` を使用します。

XIAO SAMD21を使う場合は、検索欄に `Seeed SAMD` と入力し、**Seeed SAMD Boards** をインストールしてください。

#### 4. ボードを選択する

インストールが終わったら、**ツール > ボード** から使用するボードを選択します。

- XIAO RP2040の場合： **Seeed Studio XIAO RP2040**
- XIAO SAMD21の場合： **Seeed Studio XIAO SAMD21** または **Seeeduino XIAO**

この設定により、Arduino IDEが「今から選択したXIAO向けにコンパイルして書き込む」と判断できるようになります。

#### 5. USBケーブルで接続し、ポートを選択する

XIAO RP2040またはXIAO SAMD21をUSB Type-CケーブルでPCに接続します。
このとき、充電専用ケーブルではなく、データ通信に対応したUSBケーブルを使ってください。

接続後、**ツール > ポート** から接続したXIAOに対応するポートを選択します。
Windowsでは `COM3` 以降のような名前で表示されることが多いです。

#### 6. 書き込みに失敗する場合

書き込みに失敗する場合は、使用しているボードに合わせてブートローダモードに入れてから再度書き込みます。

XIAO RP2040の場合：
基板上の **BOOT** ボタンを押しながらUSB接続すると、PC上に `RPI-RP2` というドライブが表示されます。その状態でArduino IDEから再度アップロードを試してください。

XIAO SAMD21の場合：
`RPI-RP2` ドライブは表示されません。PCに接続したまま、基板上の **RST** パッドをピンセットやジャンパ線で素早く2回ショートするとブートローダモードに入り、書き込み用のポートが再表示されます。その状態でArduino IDEから再度アップロードを試してください。

### 実習基板の配線概要

この教材で使う実習基板では、XIAO RP2040またはXIAO SAMD21の各ピンがあらかじめLED、ボタン、センサ用コネクタなどにつながっています。そのため、ブレッドボードで毎回配線を組む代わりに、プログラムから対応するピンを指定するだけで各部品を動かしたり、センサの値を読み取ったりできます。

主な接続は次の通りです。

| XIAO RP2040 / XIAO SAMD21のピン | 基板上の接続先 | プログラムでの主な使い方 |
|---|---|---|
| D0 | LED 1 | `digitalWrite()` で点灯・消灯する |
| D1 | LED 2 | `digitalWrite()` で点灯・消灯する |
| D2 | LED 3 | `digitalWrite()` で点灯・消灯する |
| D3 / A3 | 超音波センサのアナログ出力 | `analogRead()` で距離に応じた電圧を読む |
| D4 / SDA | SHT31などのI2Cデータ線 | `Wire` ライブラリで通信する |
| D5 / SCL | SHT31などのI2Cクロック線 | `Wire` ライブラリで通信する |
| D7 / RX | 超音波センサのUART出力 | シリアル通信でデータを受け取る |
| D8 | 超音波センサのPWM出力 | `pulseIn()` でパルス幅を読む |
| D9 | タクトスイッチ | `digitalRead()` で押されたかを読む |
| 3V3 | センサやプルアップ抵抗の電源 | 3.3Vを供給する |
| GND | 各部品のGND | 回路の基準となる0Vにつなぐ |

この教材で使用する範囲では、XIAO RP2040とXIAO SAMD21のどちらも、D4/D5がI2C、D6/D7がUART、D3がアナログ入力として使えます。公式ピン表でも同じ役割のピンとして示されています。ただし、どちらのボードもGPIOに3.3Vを超える電圧を入れないでください。

参考：
- Seeed Studio公式 XIAO RP2040: https://wiki.seeedstudio.com/XIAO-RP2040/
- Seeed Studio公式 XIAO SAMD21: https://wiki.seeedstudio.com/Seeeduino-XIAO/

## Lesson 01: LEDを点灯させる

### このレッスンの目標
- マイコン（マイクロコントローラ）の概念を知る
- XIAO RP2040 / XIAO SAMD21の基本構成を知る
- ピン（Pin）、HIGH/LOW の意味を理解する
- `pinMode()` と `digitalWrite()` の役割を理解する
- `setup()` と `loop()` の役割と実行順序を理解する

### 01-1. マイコンおよび XIAO RP2040 / XIAO SAMD21 とは

マイコン（マイクロコントローラ）とは、電子機器を制御するために必要な機能一式（CPU、メモリ、入出力端子など）を1つのチップに集約した小型のコンピューターです。身の回りの家電から自動車、産業用機器まで、あらゆる製品に組み込まれて動作の制御を担っています。あらかじめ指定されたプログラムに従って、センサーからの入力を処理したり、モーターやLEDなどへ信号を出力したりするのが主な役割です。

XIAO RP2040 は、Seeed Studio社が開発した小型のマイコンボードです（Arduinoプラットフォームでプログラミングが可能です）。
XIAO SAMD21も同じXIAOシリーズの小型マイコンボードで、Arduino IDEから同じようにプログラムを書き込めます。

主な特徴：
- PCとUSB接続し、作成したプログラムを書き込むことができる
- 基板の縁にある端子をピン（Pin）と呼び、ここを経由して電圧の入出力を行う
- LEDの点灯やセンサー情報の読み取りなど、外部部品を制御できる

各ピンの役割や接続先については、下図および概要を参照してください。

![XIAO RP2040 のピン配置](images/XIAORP2040.jpg)

上の図はXIAO RP2040のピン配置です。XIAO SAMD21を使う場合も、この教材で使うD0、D1、D2、D3、D4、D5、D7、D8、D9というピン名は同じように使えます。ただし、ボード上の内蔵LEDやブート操作など、基板自身の細かい仕様はRP2040とSAMD21で異なります。

主に使用するピンとその役割：
- D0〜D10（デジタルピン）： デジタル入出力（HIGH/LOW）によるLEDの点灯、およびスイッチの入力判定などに使用します。
- A0〜A3（アナログピン）： センサーなどから連続的な電圧変化を読み取る場合に使用します。
- 3V3： 3.3Vの電源を出力するためのピンです。
- GND（グラウンド）： 回路の基準となる0Vのピンです。各種電子部品を電気的にマイコンと構成するための電気の戻り道となります。
- 5V： USB接続から供給されている5V電圧を出力するピンです。


今回の実習で使用する部品の接続先：
- D0 ピン： LED 1
- D1 ピン： LED 2
- D2 ピン： LED 3
- GND ピン： 各部品をつなぐ電気の戻り道（0Vの基準点）

### 01-2. ピン「D0」とは

ピンとは、マイコンボードが外部の電子部品（LEDやスイッチなど）と電気的にやり取りするための窓口です。

サンプルコードに出てくる `D0` は、複数あるピンの中の「0番のデジタルピン」を指します（DはDigitalの略です）。

`D0` ピンで想定される役割：
- 電圧を出力する → `digitalWrite()` を用いてLEDを点灯させるなど
- 外部の電圧を読み取る → `digitalRead()` を用いてスイッチの状態を調べるなど

今回のプログラムでは、このD0ピンからLEDに電力を供給して点灯させることを目的とします。

### 01-3. HIGH と LOW の違い

デジタルピンは、基本的に「2つの状態」のいずれかを取ります。これが HIGH と LOW です。

| 状態 | 電圧 | 意味 |
|------|------|----------------|
| HIGH | 約3.3V | 電圧がかかっている状態（オン） |
| LOW | 0V | 電圧がかかっていない状態（オフ） |

回路が成立していれば、HIGHのときにLEDに電流が流れて点灯し、LOWのときに消灯します。

### 01-4. `pinMode()` 関数

関数とは、マイコンに特定の処理を実行させるための命令のまとまりです。

```cpp
pinMode(D0, OUTPUT);
```

この命令は「D0ピンを OUTPUT（出力用）に設定する」という意味です。

| カッコの中身（引数） | 対象 | 例 |
|----------------|----------------|-----|
| 第1引数（左側：`D0`） | どのピンの設定を変えるか | D0, D1, D2 など |
| 第2引数（右側：`OUTPUT`） | そのピンをどのような役割にするか | OUTPUT（出力用） または INPUT（入力用） |

OUTPUT に設定する理由：
LEDを点灯させるためには、マイコン側からLEDに向かって電圧を「出力」する必要があるためです。

### 01-5. `digitalWrite()` 関数

```cpp
digitalWrite(D0, HIGH);
```

こちらは「D0ピンから HIGH の電圧を出力する」という意味の関数です。

| カッコの中身（引数） | 対象 | 例 |
|----------------|----------------|-----|
| 第1引数（左側：`D0`） | どこから信号を出すか | D0, D1 など |
| 第2引数（右側：`HIGH`） | 出力状態 | HIGH（オン）, LOW（オフ） |

プログラム上での動作：
- `digitalWrite(D0, HIGH)` → D0から電圧が出力され、LED が 点灯 します。
- `digitalWrite(D0, LOW)` → D0からの電圧供給が止まり、LED が 消灯 します。

### 01-6. `setup()`と`loop()`という２つの重要ブロック

Arduinoのプログラムには、必ず次の2つの関数（ブロック）が含まれます。

```cpp
void setup() {
    // マイコン起動時に【1回だけ】実行される初期設定の場所
}

void loop() {
    // setup() の後、【何度も繰り返し】実行されるメイン処理の場所
}
```

プログラムが実行される順番：
1. マイコンの電源が入る
2. `setup()` を一通り実行して、ピンの設定（OUTPUT/INPUT等）を行う
3. `loop()` を実行する
4. `loop()` が最後まで到達したら、再び `loop()` の先頭に戻って繰り返し実行する

### 01-7. コード例全体の流れ

```cpp
void setup(){
    pinMode(D0, OUTPUT);  // ① 起動時に1回だけ実行。
                          //    D0 ピンを「出力用」にセットする。
}

void loop(){
    digitalWrite(D0, HIGH);  // ② そのあと継続して繰り返し実行。
                             //    D0 ピンから電圧を出力し続ける。
}
```

この仕組みにより、マイコンに通電している間はLEDが点灯し続けます。

### 01-8. 回路の仕組み

電気の通り道（回路）：
```
[D0 ピン] → [抵抗 (過電流を防ぐため)] → [LEDのアノード(＋側)] → [LEDのカソード(－側)] → [GND (グラウンド: 0V)]
```
この流れで1つのループが形成されることで、電気が流れてLEDが光ります。

### 01-9. 演習問題


ここまでの知識を活用し、D1 ピンに接続された LED（LED 2）を点灯させるプログラムを作成してください。

## Lesson 02: `#define` と `delay()` を使う

### このレッスンの目標
- `#define` を使い、ピン番号や数値の別名を定義してコードを読みやすくする
- `delay()` を使ってプログラムを待機させる方法を知る
- LEDを指定間隔で点滅させる


### 02-1. `#define` とは

`#define` は、コンパイル（人が書いたプログラムをマイコン用の言語に翻訳する作業）が始まる直前に、特定の文字列を置き換えてくれる機能です。
変数のように値を保持するのではなく、単なる「文字列の置き換え」として動作します。

```cpp
#define LEDPin1 D0
```

コード内でこのように記述すると、以降のプログラムにおいて `LEDPin1` という文字列が使用されている部分は、コンパイル時にすべて自動で `D0` に置き換えられます。

`#define` を利用することで、たとえば「このD0ピンは何の用途なのか」といった情報に対して「わかりやすい別名」をつけることができます。
意図が明確になるため、後からコードを見返したり、他人が読んだりする際の可読性が大きく向上します。

### 02-2. `delay()` とは

`delay()` は、指定した時間のあいだプログラムの処理を一時停止（待機）させる関数です。
時間はミリ秒（1000ミリ秒 ＝ 1秒）で指定します。

```cpp
delay(1000);
```

このように記述すると「1000ミリ秒（＝1秒）待つ」という意味になります。
待機している間、マイコンは次の処理へ進みません。「LEDを点灯させてから少し待機し、消灯させてまた待機する」という処理をループさせることで、LEDを点滅させることができます。

### 02-3. 全体の動作を確認する

`example_code_2.ino` は、特定のピンを出力用に設定してLEDを点灯させ、1秒間待機するシンプルなプログラムです。

```cpp
#define LEDPin1 D0

void setup(){
    pinMode(LEDPin1,OUTPUT);
}

void loop(){
    digitalWrite(LEDPin1,HIGH);
    delay(1000);
    digitalWrite(LEDPin1,LOW);
    delay(1000);
}
```

実行フロー：
1. `#define` により、`D0` ピンに `LEDPin1` という分かりやすい名前を付ける
2. `setup()` 内で、`LEDPin1`（つまり D0ピン）を「OUTPUT（出力用）」に設定する
3. `loop()` 内で、`LEDPin1` から HIGH（3.3V）を出力しLEDを点灯させる
4. `delay(1000)` により、その状態で1秒間待機する
5. 続いて `LEDPin1` を LOW（0V）にしてLEDを消灯させる
6. `delay(1000)` により、消灯させた状態でさらに1秒間待機する
7. `loop()` の最後まで到達したため、また最初に戻る（点滅を繰り返す）

### 02-4. 演習問題


ここまでの知識を応用して、D0、D1、D2の3つのピンに接続されたLEDを、1秒ごとに順番に点灯（入れ替え）させるプログラムを作成してください。

条件：
- 3つのピンをすべて `#define` を使って定義する
- 1 秒ごとに点灯する LED を切り替える
- 点灯していない LED は消灯しておく
- D0 → D1 → D2 の順で繰り返す

## Lesson 03: `const`・配列・変数の型を使う

### このレッスンの目標
- 複数のピン変数を効率よく扱うための「配列」を習得する
- 変数の「型」の概念を理解する
- `int` や `uint8_t` といった型の用途を整理する


### 03-1. `const` とは

`const`（定数を意味する constant の略）は、「この変数の値は後から変更しない」と宣言するための修飾子です。
プログラムの実行中に誤って値を変更しようとすると、コンパイルエラーとして警告してくれます。

たとえば、今回のコードでは次のようにLEDが接続されているピンを配列で管理します。

```cpp
const uint8_t led[3] = {D0, D1, D2};
```

ここで `led` に入っている `D0`、`D1`、`D2` は、基板上でLEDが接続されているピン番号です。
これらはプログラムの実行中に変化する値ではなく、配線によって決まっている固定の設定値です。

`const` を使う主な理由は、このような「途中で変わるべきではない値」を、普通の変数と区別するためです。
値が変わらないことをコード上で明示しておくと、あとから読む人にも「これは固定の設定値なのだ」と伝わりやすくなります。
また、うっかり `led[0] = D5;` のように別の値を代入してしまった場合も、コンパイル時にエラーとして気づくことができます。

つまり `const` は、バグを防ぎつつ、コードの読みやすさや保守しやすさを高めるための工夫です。

### 03-2. 配列とは

配列は、複数の同じ種類のデータを、1つの名前でまとめて管理するための仕組みです。
今回のようにLEDが3つある場合、ピン番号を1つずつ別の変数として書くこともできます。

```cpp
uint8_t led1 = D0;
uint8_t led2 = D1;
uint8_t led3 = D2;
```

この書き方でも動作しますが、LEDの数が増えると変数名も増えていきます。
また、3つのLEDに同じ処理をしたい場合でも、`led1`、`led2`、`led3` に対して似たような処理を何度も書く必要があります。

そこで、次のように配列を使うと、3つのピン番号を `led` という1つの名前でまとめて扱えます。

```cpp
uint8_t led[3] = {D0, D1, D2};
```

この記述は、「`led` という名前の箱を3つ用意し、その中に `D0`、`D1`、`D2` を順番に入れる」という意味です。
`[3]` は、配列の中にデータを3個入れることを表しています。

配列の中のデータを取り出すときは、何番目のデータかを `[]` の中に書きます。
この番号を インデックス と呼びます。
注意点として、配列のインデックスは 1 ではなく 0 から始まります。

| 書き方 | 取り出される値 | 実習基板での意味 |
|---|---|---|
| `led[0]` | `D0` | LED 1 のピン |
| `led[1]` | `D1` | LED 2 のピン |
| `led[2]` | `D2` | LED 3 のピン |

たとえば、次のように書くと、配列の0番目に入っている `D0` ピンを出力用に設定します。

```cpp
pinMode(led[0], OUTPUT);
```

これは、次のように直接 `D0` と書いた場合と同じ意味です。

```cpp
pinMode(D0, OUTPUT);
```

配列を使う大きな利点は、後で学ぶ `for` 文と組み合わせやすいことです。
たとえば `led[0]`、`led[1]`、`led[2]` のように番号だけを変えながら同じ処理を繰り返せるため、LEDが増えてもコードをすっきり書けます。

### 03-3. 変数の「型」とは

プログラミングにおける変数には、その変数が「どのような性質のデータを格納するか」を定めた 型 が存在します。
「小規模な整数用」「負の数も扱える整数用」など、様々な型があります。

今回のコードでは `uint8_t` という型を使用しています。

```cpp
uint8_t led[3] = {D0, D1, D2};
```

ここで出てくる `8` は、「8ビット」というデータの大きさを表しています。
ビットとは、コンピュータが情報を扱うときの最小単位で、1ビットには `0` または `1` のどちらか1つだけを入れることができます。

1ビットだけでは `0` と `1` の2通りしか表せませんが、ビット数が増えると表せる値の種類も増えます。
たとえば、8ビットでは `0` と `1` を入れられる場所が8個あるため、表せる組み合わせは `2^8 = 256` 通りになります。
そのため、8ビットでは `0` から `255` までの値を表すことができます。
この教材では、ピン番号やLEDの個数のような小さい整数を扱うため、「8ビット分の大きさがあれば十分」と考えることができます。

`uint8_t` の構成要素を確認すると、次のようになります：
- `u` = unsigned（符号なし、つまり負数を含まない）
- `int` = 整数型
- `8` = 8ビット（容量が小さい）
- `t` = type（型）

すなわち、`uint8_t` は 0 から 255 までの正の整数のみを格納する型 です。

`uint8_t` を選択する理由：
- ピンの番号やLEDの個数は「0〜255」の範囲に収まる正の数であるため
- 必要以上のメモリ（データ容量）を消費せず、適切なサイズで定義できるため
- 「この変数には負の値は入らない」という制約を明示化できるため

ここでメモリの節約につながっているのは、`uint` であること自体ではなく、`8` によって「8ビット分の大きさでよい」と指定している点です。
つまり、`uint8_t` は「負の数を扱わない」ことと、「0〜255まで入れば十分なので小さい容量で扱う」ことを同時に表しています。

### 03-4. `int` と `uint8_t` の使い分け

マイコンのプログラミングで最も一般的に用いられる整数型が `int`（イント）です。  
計算やループのカウンタ（回数カウント）など、広範な用途において使用され、万能なように思えます。

ただし、今回のコードでは `int` ではなく、あえて `uint8_t` という型を使用しています。

| 型 | 入れられる数値の範囲 | 適した用途 |
|---|---|---|
| `int` | 環境により異なりますが、多くは −3万〜＋3万 程度の範囲 | 計算や、負の値が含まれる可能性のある一般的な整数処理 |
| `uint8_t` | 0〜255 | 0以上の小さい整数（ピン番号変数、カウンタ変数、色の階調など） |

この使い分けの意図：
`int` を使用しても同様に動作しますが、プログラミングにおいては「この変数は絶対に負にならないし、255以上の大きな数も扱わない」と明示する目的で、特定の制約を持たせた型（ここでは `uint8_t`）を選択することがあります。
また、必要以上に大きな型を使わないことで、メモリ使用量を小さくできる場合があります。
コードの可読性や安全性を高めつつ、マイコンの限られたメモリを意識する工夫の1つです。

### 03-5. `for` 文による繰り返し処理

`for` 文は、「同じ処理を決まった回数だけ繰り返したい」ときに使う構文です。
たとえば、D0ピンに接続されたLEDを3回点滅させたい場合、`for` 文を使わずに書くと次のようになります。

```cpp
digitalWrite(D0, HIGH);
delay(1000);
digitalWrite(D0, LOW);
delay(1000);

digitalWrite(D0, HIGH);
delay(1000);
digitalWrite(D0, LOW);
delay(1000);

digitalWrite(D0, HIGH);
delay(1000);
digitalWrite(D0, LOW);
delay(1000);
```

このように3回程度なら手で書けますが、10回、100回と増えると大変です。
そこで `for` 文を使うと、次のように「3回繰り返す」とまとめて書くことができます。

```cpp
for (uint8_t i = 0; i < 3; i++) {
    digitalWrite(D0, HIGH);
    delay(1000);
    digitalWrite(D0, LOW);
    delay(1000);
}
```

`for` 文のカッコの中は、次の3つの部分に分かれています。

| 部分 | 意味 | 今回の例 |
|---|---|---|
| `uint8_t i = 0` | 初期値の設定 | `i` を 0 から始める |
| `i < 3` | 繰り返しを続ける条件 | `i` が 3 より小さい間だけ続ける |
| `i++` | 1回終わるたびに行う処理 | `i` を 1 ずつ増やす |

このとき、`i` の値は次のように変化します。

| 何回目の繰り返し | `i` の値 | 条件 `i < 3` |
|---|---|---|
| 1回目 | 0 | 成り立つ |
| 2回目 | 1 | 成り立つ |
| 3回目 | 2 | 成り立つ |
| 4回目に進もうとする時 | 3 | 成り立たないので終了 |

つまり、`for (uint8_t i = 0; i < 3; i++)` は「`i` を 0、1、2 と変えながら、中の処理を3回実行する」という意味になります。

配列と組み合わせると、`i` をそのままインデックスとして使うことができます。

```cpp
for (uint8_t i = 0; i < 3; i++) {
    pinMode(led[i], OUTPUT);
}
```

このコードでは、`i` が 0、1、2 と変わるため、実際には次の3つの処理を順番に行っているのと同じです。

```cpp
pinMode(led[0], OUTPUT);
pinMode(led[1], OUTPUT);
pinMode(led[2], OUTPUT);
```

このように、`for` 文を使うと、似たような処理を何度も書かずに整理できます。

### 03-6. 全体の動作を確認する

```cpp
const uint8_t led[3] = {D0, D1, D2};

void setup() {
    // インデックス 0 から 2 まで同じ処理を繰り返し、配列内のピン全てを「出力」に設定する
    for(uint8_t i = 0; i < 3; i++) {
        pinMode(led[i], OUTPUT);
    }
}

void loop() {
    // 0番目のLEDを点灯させ、1秒待機した後に消灯する
    digitalWrite(led[0], HIGH);
    delay(1000);
    digitalWrite(led[0], LOW);
    
    // 1番目のLEDを点灯させ、1秒待機した後に消灯する
    digitalWrite(led[1], HIGH);
    delay(1000);
    digitalWrite(led[1], LOW);
    
    // 2番目のLEDを点灯させ、1秒待機した後に消灯する
    digitalWrite(led[2], HIGH);
    delay(1000);
    digitalWrite(led[2], LOW);
}
```

実行フロー：
1. `led` という名前の配列に、定数として `D0`, `D1`, `D2` のピン情報を格納する
2. `setup()` の中で `for` ループを使用し、`led[0]`〜`led[2]` のピンすべてを「OUTPUT（出力用）」に設定する
3. `loop()` の中で、0 番目のLEDを `HIGH`(点灯)にし、1秒待って `LOW`(消灯)にする
4. 続いて 1 番目のLEDに対し同じ処理（点灯→1秒待機→消灯）を行う
5. 最後に 2 番目のLEDに対し同じ処理を行う
6. `loop()` は終了後に再び先頭から繰り返すため、結果として「LEDがひとつずつ順番に光ながら移動する」アニメーションになります。

## Lesson 04: `digitalRead()` による入力の読み取り

### このレッスンの目標
- `digitalRead()` の用途と利用方法を理解する
- スイッチの入力状態とLEDの出力を連携させる
- 入力ピンにおける「プルアップ抵抗」の役割を理解する



### 04-1. `digitalRead()` とは

これまで使用してきた `digitalWrite`（電圧を出力する）とは逆で、`digitalRead()` は外部からの電圧の状態を「読み取る」関数です。  
この関数を使用することで、マイコンは指定されたピンの現在の状態（HIGH または LOW）を取得できます。

### 04-2. プルアップ抵抗の重要性

入力用のピン（スイッチなど）を扱う際に問題となるのが、「スイッチが押されておらず、かつ外部のどこにも接続されていない宙ぶらりんの状態（オープン状態）」です。
マイコンの入力ピンは高感度に設計されているため、オープン状態だと周囲のノイズを拾い、「HIGH か LOW か」が不定になってしまう（バタつく）現象が発生します。

これを防止するための回路的な工夫が プルアップ です。
ピンが不定にならないよう、「スイッチが押されていないときは、内部または外部の抵抗器を通してあらかじめ電圧を HIGH の状態に引き上げておく」という設計手法です。

プルアップ回路では、入力ピンを抵抗を通して 3.3V 側につないでおきます。
一方で、スイッチは入力ピンと GND 側をつなぐように配置します。

イメージとしては次のような接続です。

```text
3.3V ──[プルアップ抵抗]── 入力ピン ──[スイッチ]── GND
```

スイッチを押していないときは、入力ピンはプルアップ抵抗を通して 3.3V 側につながっています。
そのため、入力ピンには HIGH の電圧がかかり、`digitalRead()` の結果は HIGH になります。

スイッチを押すと、入力ピンが GND に直接つながります。
GND は 0V なので、入力ピンの電圧は LOW になり、`digitalRead()` の結果も LOW になります。

ここで抵抗が入っている理由は、スイッチを押したときに 3.3V と GND がそのまま直結されるのを防ぐためです。
抵抗があることで、電流が流れすぎることを防ぎながら、入力ピンの状態を安定して HIGH に保つことができます。

これにより、入力状態が安定して監視できます。
- スイッチを押していない時 → あらかじめ HIGH 状態が維持されているため検出結果は「HIGH」
- スイッチを押した時 → 経路がGND（0V）に短絡するため、検出結果は「LOW」に変化する

今回の演習コードでも、この仕組みを利用してボタンの押下判定を行っています。

### 04-3. 全体の動作を確認する

```cpp
#define button D9
uint8_t led[3] = {D0, D1, D2};

void setup() {
    for(uint8_t i = 0; i < 3; i++) {
        pinMode(led[i], OUTPUT);
    }
    pinMode(button, INPUT);  // D9 を「入力用」に設定
}

void loop() {
    // もしボタンピンの読み取り状態が「LOW（押下されている）」であれば
    if(digitalRead(button) == LOW){
        for(uint8_t i = 0; i < 3; i++) {
            digitalWrite(led[i], HIGH);
            delay(500); // 0.5秒おきに点灯
            digitalWrite(led[i],LOW);
            delay(500);
        }
    } else {
        // ボタンが押下されていない時は、すべてのLEDを消灯する
        for(uint8_t i = 0; i < 3; i++) {
            digitalWrite(led[i], LOW);
        }
    }
}
```

実行フロー：
1. `#define` により `button` を `D9` ピンとして定義する
2. LED出力用ピンは配列変数 `led` に格納する
3. `setup()` の中で LED を出力（OUTPUT）、ボタンピンを入力（INPUT）に設定する
4. `loop()` の分岐（`if` 文）内において、`digitalRead()` でボタンの状態を読み取る
5. 「条件が LOW（ボタンが押されている）」と判定できた場合は、3つのLEDを0.5秒間隔で順に点灯させる
6. 「条件がそれ以外（ボタンが押されていない）」と判定された場合は、3つのLEDをすべて消灯させる

### 04-4. グローバル変数とローカル変数の違い

演習問題に取り組む前に、変数のスコープ（有効範囲）について確認しておきます。プログラム内で変数を宣言する場所によって、データの保持期間とアクセスできる範囲が異なります。

グローバル変数：
`setup()` や `loop()` といった関数の「外側」（通常はプログラムの上部）で宣言する変数です。プログラム全体のどこからでも参照や変更が可能であり、マイコンが稼働している間は常に値を保持し続けます。
「これまでにボタンが押された回数」など、繰り返し実行される `loop()` の周期をまたいで記憶し続けたい値の保存に適しています。

```cpp
// ==== グローバル変数の例 ====
uint8_t count = 0; // すべての関数の外で宣言する

void setup() {
    count = 1; // どこからでも上書き・読み出しが可能
}

void loop() {
    count++; // loop関数が繰り返されるたびに、値が上書き保存されて増え続ける（記憶される）
}
```

ローカル変数：
関数や `for` 文などのブロックの「内側（ `{` と `}` の間 ）」で宣言する変数です。宣言されたブロックの中だけで有効であり、処理がそのブロックを抜けると同時に変数は破棄（リセット）されます。

```cpp
// ==== ローカル変数の例 ====
void loop() {
    uint8_t num = 0; // loop関数の中で宣言（ローカル変数）
    num++; // 1増やすが、loop関数が最後まで行くと変数は消滅する

    // 毎回 loop の最初に新しく 0 として作られるため、いつまで経っても 1 にしかならない
    
    for (uint8_t i = 0; i < 3; i++) {
        // 変数 i はこの for 文の { } の中でしか使えない
    }
    // ここで変数 i を使おうとすると「宣言されていません」というエラーになる
}
```

これらを踏まえ、次の演習問題では「押下回数」を安全に記憶し続けるために、どちらの変数が必要かを意識して論理を組み立ててください。

### 04-5. while文（条件付きループ）の使い方

これまでに学んだ `for` 文は「決まった回数」の繰り返しに使いました。一方で `while`文 は「条件が満たされている間、ずっと繰り返す」ための構文です。

```cpp
while (条件式) {
  // 条件が真（正しい）である限り、この中の処理を延々と繰り返す
}
```

例えば、「ボタンが押されている（`LOW`である）間、ずっと待機し続けたい」場合は以下のように記述します。

```cpp
while (digitalRead(button) == LOW) {
  delay(10); // 10ミリ秒だけ待つ（これを繰り返す）
}
```

マイコンは上から順にプログラムを実行しますが、`while` にたどり着くと、`digitalRead(button) == LOW` という条件が成立している（＝ボタンが押されたままの）間は、ブロックの中身（`delay(10)`）を繰り返し続けます。
そして指が離されて状態が `HIGH` に変わると、条件から外れるため `while` のループから抜け出し、次の行へと進みます。

これを利用することで、「ボタンの長押し」を意図的に待機させて、処理が何度も実行されてしまうのを防ぐことができます。

### 04-6. 演習問題


「ボタンが 5回 押されたら、D0 の LED が（継続して）点灯する」というプログラムを実装してください。

ヒント：
- `loop()` より上部に、ボタンが押された回数を数えるグローバル変数を定義して初期値を設定します（例: `uint8_t count = 0;`）。
- `loop()` の内部で `digitalRead(button)` を使い、ボタンが `LOW`（押されている）かどうかを判定します。
- ただし `LOW` かどうかのみで分岐させて単純にカウントを増やすと、マイコンの処理が速すぎて「1回ボタンを押して離すまでの間」に何度もカウントされてしまいます。
- これを防ぐため、カウントを増やした直後に「指が離されるまで何もせず待つ」という工夫をします。
  - `while`文を使って `while (digitalRead(button) == LOW) { delay(10); }` と書くことで、ボタンが押されている間はずっとブロック内で待機させることができます。
- カウンタの変数が 5 に達した場合は `digitalWrite(D0, HIGH)` で LED を点灯させます。

想定される思考手順：
1. `digitalRead()` でボタンが押されたか確認する
2. 押されていたら、カウントを「＋１」する
3. `while` 文を使って、指が離れる（HIGHに戻る）まで待機する
4. カウントが目標の5回に到達したら、対象のLEDに電圧を出力して点灯させる

### このレッスンの目標

- UART通信の特徴を知る（I2CやSPIなどの存在を知る）

### 05-1. シリアル通信とパラレル通信の違い

マイコンと他の機器（今回はPC）でデータをやり取りする方法には、大きく分けて「パラレル通信」と「シリアル通信」の2種類があります。

- パラレル通信： 複数の信号線を使い、一度にたくさんのデータを並行してドサッと送る方式。速度は出しやすいが、線が多くなり配線が複雑になります。
- シリアル通信： 1〜2本の少ない信号線を使い、データを1列に並べて順番にチビチビと送る方式。配線がシンプルで長距離でもエラーが起きにくいのが特徴です。

現代の電子機器は高速化技術が進歩したため、USB（Universal Serial Busの略）に代表されるようにシリアル通信が主流となっています。

### 05-2. USBケーブルの中身と UART とは

PCとXIAO（RP2040 / SAMD21）は太いUSBケーブルで繋がれているため「何本もの線でパラレル通信しているのでは？」と直感的に思うかもしれません。しかし、実際にデータ通信の主役となっているのは「送信（TX）」と「受信（RX）」の2本の線（シリアル通信）です。

今回Arduinoで主に使用している通信方式は UART（ユーアート） と呼ばれます。
UARTは、TX（送信）とRX（受信）の2本の線をクロスさせて繋ぎ、1対1でシンプルにデータを送り合う古くからある強力な通信規格です。

なお、「シリアル通信」という言葉は総称です。UARTの他にも、用途に応じて以下のような様々なシリアル通信の手法が存在することを頭の片隅に置いておきましょう。
- I2C（アイ・スクエア・シー）： 2本の線で複数のセンサーと通信するのが得意
- SPI（エス・ピー・アイ）： 3〜4本の線を使い、I2Cよりも高速に通信するのが得意

### 05-3. Serial 関数について

Arduinoでは、UART通信を使ってPCとやり取りするために Serial という関数群が用意されています。デバッグ（プログラムが正しく動いているかの確認）において非常に重宝します。

`Serial.begin(9600);`
- 意味：PCとの通信速度（ボーレート）を 9600 bps に設定して、通信を開始します。
- 配置：起動時に1回だけ実行すればよいので `setup()` の中に書きます。この速度がPC側の設定と一致していないと、文字化けしてしまいます。

`Serial.print("文字列");` / `Serial.println("文字列");`
- 意味：カッコの中の文字や変数の数値をPCに向けて送信します。
- print は改行なし、println は送信後に改行（Line New）が入ります。

### 05-4. 全体の動作を確認する

example_code_5.ino では、前回の演習をもとに「ボタンを押した回数」をPCに送信するプログラムを作成しました。

```cpp
#define button D9

// 必要なグローバル変数は「カウント」だけ
uint8_t count = 0;

void setup() {
    Serial.begin(9600);      // PCとの通信を9600bpsで開始
    pinMode(D0, OUTPUT);
    pinMode(button, INPUT);
}

void loop() {
  // ボタンが押されているかをチェック
  if (digitalRead(button) == LOW) {
    count++; // カウントを1増やす
    
    // 指が離されるまで待機する（連打・長押し判定を防ぐ）
    while (digitalRead(button) == LOW) {
        delay(10);
    }
    // 現在のカウント数をPCへ送信（文字と変数を組み合わせる）
    Serial.print("ボタンが");
    Serial.print(count);
    Serial.println("回押されました");
  }
  
}
```

実行フロー：
1. setup() の先頭で `Serial.begin(9600)` を実行し、PCへの送信準備を整える
2. loop() の中で毎周期ボタンの監視を行う
3. ボタンが押されたら `count` を1増やし、指が離れるまで `while` で待機する
4. `Serial.print("ボタンが");` で改行せずに文字を送信
5. `Serial.print(count);` で現在の `count` の数値を送信
6. `Serial.println("回押されました");` で文字を送信し、最後に改行する
7. Arduino IDEの設定画面（シリアルモニタ）を開いて通信速度を 9600 に合わせると、「ボタンが3回押されました」のように送信結果が文字として表示される

`Serial.print()`と`Serial.println()`の違いを理解するために`Serial.println("回押されました");`を`Serial.print("回押されました");`に変更したり、`Serial.print(count);`を`Serial.println(count);`に変えたりしてみましょう。

## Lesson 06: 超音波センサで距離を測る

- `analogRead()` でアナログ値を取得する方法を知る

このLessonで使う基板上の接続：

| 信号 | XIAO RP2040 / XIAO SAMD21のピン | プログラムで使う名前 |

| 超音波センサのアナログ出力 | D3 / A3 | `analog_Pin` |
| 超音波センサのPWM出力 | D8 | `PWM_Pin` |
| センサ電源 | 3V3 | 電源として使用 |
| センサGND | GND | 回路の基準 |

### 06-1. 超音波センサの出力について

超音波センサは、超音波を発信し、物体からの反射を検出することで距離を測定します。今回使用する超音波センサは次の3種類の出力に対応しています。

- **PWM出力**：パルス幅（HIGHの時間）で距離を表現。パルス幅が長いほど遠いことを示します。
- **アナログ出力**：電圧値で距離を表現。距離に応じて0V～3.3Vなどの範囲で変化します。
- **UART出力**：シリアル通信（TX/RX）でデジタル値として距離データを送信します。PCや他のマイコンと直接データ通信が可能です。

#### 【用語解説】PWM信号・アナログ信号とは？
- **PWM（Pulse Width Modulation）信号**：デジタル信号のON/OFF（HIGH/LOW）の時間幅を変化させることで情報を伝える方式。超音波センサでは、1回のパルスのHIGH時間が距離に比例します。
- **アナログ信号**：連続的に変化する電圧値で情報を伝える方式。センサの出力電圧が距離に比例します。

### 06-2. `pulseIn()` と `analogRead()` の使い方

- `pulseIn(pin, HIGH)` は、指定したピンがHIGHになっている時間（マイクロ秒単位）を返します。超音波センサのPWM出力ピンに使うことで、パルス幅から距離を計算できます。
- `analogRead(pin)` は、指定したアナログピンの電圧値を数値で返します。戻り値の範囲は設定によって変わり、10bit設定なら `0` ～ `1023`、12bit設定なら `0` ～ `4095` になります。アナログ出力ピンに使うことで、電圧値から距離を計算できます。

#### 【関数解説】
- `pulseIn()`：第1引数にピン番号、第2引数にHIGHまたはLOWを指定。ピンが指定した状態になっている時間（μs）を返す。
- `analogRead()`：第1引数にアナログピン番号を指定。ピンの電圧をADC（A/Dコンバータ）でデジタル値に変換して返す。

### 06-3. マイコンのピンによる電圧の読み取りと計算方法

マイコンのアナログピン（A0など）は、外部から入力された電圧を「A/Dコンバータ（ADC）」という回路でデジタル値（数値）に変換して読み取ります。
XIAO RP2040もXIAO SAMD21も3.3V系のボードなので、アナログ入力で扱う電圧の上限は基本的に3.3Vです。3.3Vを超える電圧を入力しないでください。

この教材のサンプル解答では、アナログ値を距離に換算するときに `1023.0` で割る式が出てきます。これは `analogRead()` の値を10bit、つまり `0` ～ `1023` の範囲として扱う場合の式です。XIAO RP2040でもXIAO SAMD21でも、教材の式をそのまま使う場合は10bitとして考えます。

一方で、RP2040やSAMD21のADCは12bit相当の読み取りにも対応しています。`setup()` の中で次のように設定した場合、`analogRead()` の戻り値は `0` ～ `4095` の範囲として扱います。

```cpp
analogReadResolution(12);
```

その場合は、距離換算や電圧換算で使う最大値も `1023` ではなく `4095` に読み替えてください。

**実際の電圧値（V）への計算式**
読み取った数値から実際の電圧を求めるには、次の計算式を使います：
```
電圧(V) = analogReadの値 × 基準電圧 / (ADCの最大値)
```
例：基準電圧が `3.3V`、ADCの最大値が `1023` の場合
```
電圧(V) = analogReadの値 × 3.3 / 1023
```

例：基準電圧が `3.3V`、ADCの最大値が `4095` の場合
```
電圧(V) = analogReadの値 × 3.3 / 4095
```
このようにして、`analogRead()` で得られた数値に特定の計算をすることで、ピンにかかっている実際の電圧（V）を求めることができます。

## Lesson 07: シリアル通信（UART）によるデータ受信と文字コード

### このレッスンの目標
- 受信バッファの概念を理解する
- `Serial.available()` と `Serial.read()` の役割を理解する
- データシートからUART通信のデータフォーマットを読み解く
- ASCIIコードによる文字データから数値データへの変換手法を理解する

このLessonで使う基板上の接続：

| 信号 | XIAO RP2040 / XIAO SAMD21のピン | プログラムで使う名前 |
|---|---|---|
| 超音波センサのUART出力 | D7 / RX | `Serial1` で受信 |
| センサ電源 | 3V3 | 電源として使用 |
| センサGND | GND | 回路の基準 |

XIAO SAMD21でもD6がUARTのTX、D7がUARTのRXとして定義されています。このレッスンでは超音波センサからのデータを受け取るだけなので、D7 / RXを `Serial1` で読み取る考え方はRP2040と同じです。

### 07-1. シリアル通信の受信と「バッファ」の概念

シリアル通信において、機器からマイコンへ送信されたデータは即座にプログラムの変数に代入されるわけではありません。マイコンの内部には「受信バッファ」と呼ばれる一時的な記憶領域（メモリ上の待合室）が存在します。通信によって到着したデータは、1バイト（8ビット）ずつこのバッファに順番に蓄積されます。

ここでいう **1バイト** とは、8個のビットをまとめたデータの単位です。
Lesson 03で扱ったように、1ビットは `0` または `1` のどちらか1つを表します。
そのビットが8個集まると、`2^8 = 256` 通りの組み合わせを表せるため、1バイトでは `0` から `255` までの値を扱うことができます。

UARTのようなシリアル通信では、この1バイトを基本単位としてデータを送受信します。
今回の超音波センサでは、距離の情報が「文字」として送られてきますが、その文字も通信上は1文字ずつ1バイトのデータとして届きます。
たとえば文字の `'R'` は1バイト、文字の `'1'` も1バイト、文字の `'2'` も1バイトです。

そのため、センサから `R125\r` というデータが送られてくる場合、マイコンには次のように5個の1バイトデータとして順番に届きます。

| 到着順 | 届く文字 | 1バイトの中身として扱われる値 |
|---|---|---|
| 1番目 | `'R'` | ASCIIコードの `82` |
| 2番目 | `'1'` | ASCIIコードの `49` |
| 3番目 | `'2'` | ASCIIコードの `50` |
| 4番目 | `'5'` | ASCIIコードの `53` |
| 5番目 | `'\r'` | ASCIIコードの `13` |

つまり「5バイトのデータを受信する」とは、「1バイトのデータが5個、順番に届く」という意味です。
`Serial.read()` は、このうち先頭にある1バイトだけを1回で読み取ります。

これらを処理するために、以下の2つの関数を使用します。

- `Serial.available()`：現在、受信バッファに何バイトの未処理データが溜まっているか（読み取り可能か）を数値で返す関数です。データが存在しない場合は `0` を返します。
- `Serial.read()`：受信バッファの先頭からデータを1バイトだけ読み取り、同時にバッファからそのデータを削除する関数です。

データを受信する際は、まず `available()` でバッファにデータが到着しているかを確認し、存在する場合のみ `read()` でデータを取り出す、という手順を踏むのが原則です。

### 07-2. 超音波センサのデータ出力フォーマット

センサからどのような順番・形式でデータが送られてくるのかは、対象部品のデータシートを確認する必要があります。
今回の超音波センサ（LV-MaxSonar-EZシリーズ）のシリアル通信（Pin 5 TX）の仕様は以下の通りです。

- 非同期シリアルデータ（RS232フォーマット、0-Vccレベル）で、通信速度は9600 Baudです。
- データの形式は、ASCIIの大文字「R」から始まります。
- 続いて、インチ単位の距離を示す3桁のASCII文字の数字（最大255）が出力されます。
- 最後に、キャリッジリターン（ASCII 13）が出力されます。

これらは5バイトのパケット（データのまとまり）として連続して送信されます。具体例として、計測距離が125インチの場合、センサからは `R`, `1`, `2`, `5`, `\r`（キャリッジリターン）という順番でデータが送られてきます。 また、計測距離が8インチの場合は `R`, `0`, `0`, `8`, `\r` となり、常に3桁が維持される仕様となっています。

### 【補足】 ASCII（アスキー）コードとは？

コンピュータは内部的に「0」と「1」の数値（バイナリデータ）しか処理できません。そのため、人間が使う「文字」をコンピュータに扱わせるには、「どの数値がどの文字に対応するか」という世界共通の変換ルールが必要になります。この絶対的な対応表の代表例が **ASCII（アスキー）コード** です。

ASCIIコードは、0から127までの128個の整数値に対して、アルファベット、数字、記号、そして画面には表示されない「制御文字」をそれぞれ割り当てています。

**主要なASCIIコードの対応表（抜粋）：**

| 文字 | 10進数の値 | 分類・意味 |
| :---: | :---: | :--- |
| `\r` (CR) | 13 | 制御文字（キャリッジリターン：カーソルを行の先頭に戻す） |
| `' '` (Space)| 32 | 空白（スペース） |
| `'0'` | 48 | 数字のゼロ |
| `'1'` | 49 | 数字のイチ |
| `'9'` | 57 | 数字のキュウ |
| `'A'` | 65 | アルファベット大文字 |
| `'R'` | 82 | アルファベット大文字（※今回のセンサの開始文字） |
| `'a'` | 97 | アルファベット小文字 |

#### 文字の正体は「単なる整数値」
Arduino（C++言語）において、シングルクォーテーションで囲まれた1文字（例：`'1'` や `'R'`）は、内部的には「対応するASCIIコードの整数値」として扱われます。

- プログラムに `if (SonicData[0] == 'R')` と書いた場合、マイコン内部では `if (SonicData[0] == 82)` という数値の比較計算が実行されています。
- `Serial.read()` が文字の `'5'` を読み取ったとき、変数に格納されるのは `5` ではなく `53` です。

#### 数字の文字を、計算用の数値に変換する仕組み
ASCIIコード表を見ると、数字の `'0'` から `'9'` までは、**48から57まで連続した整数値**が規則的に割り当てられていることがわかります。この規則性を利用したのが、以下の計算式です。
```cpp
int inches = SonicData[1] - '0';
```
もし SonicData[1] に文字の '5'（ASCIIコードで53）が入っていた場合、プログラム上の '0' はコンパイラによって 48 として評価されるため、実際の計算は以下のようになります。

53 - 48 = 5

このように、基準となる '0' の文字コード（48）を引くことで、文字コードのオフセット（下駄ばき）が相殺され、純粋な計算用の数値である 5 を導き出すことができます。

### 07-3. サンプルコードの動作と数値への変換

以下のサンプルコードは、上記5バイトのパケットから「百の位」の数値を抽出する処理を実装しています。

```cpp
void setup(){
    Serial.begin(9600);
    Serial1.begin(9600);
}

void loop(){

    int SonicData[5] = {0,0,0,0,0};

    if(Serial1.available()){
        SonicData[0] = Serial1.read();
        if(SonicData[0] == 'R'){

            while(!Serial1.available());

            SonicData[1] = Serial1.read();
        }
        while(!Serial1.available());//上位桁以外のデータを破棄
        SonicData[2] = Serial1.read();
        while(!Serial1.available());
        SonicData[3] = Serial1.read();
        while(!Serial1.available());
        SonicData[4] = Serial1.read();

    }

    int inches = SonicData[1] - '0';

    Serial.println(inches);

}
```

**コードの論理構造：**
データシートの仕様から、正しいデータ群の先頭は必ず `'R'` であることが保証されています。そのため、`SonicData[0] == 'R'` という条件式でパケットの開始を検知しています。検知した後は `while(!Serial1.available());` という空のループ処理によって「次の1バイトがバッファに到着するまで待機」し、到着しだい `read()` で配列の該当箇所に格納する処理を繰り返しています。

**なぜ `SonicData[1] - '0'` で数値が得られるのか：**
`Serial.read()` が返す値は、対象となる数値そのものではなく、ASCII（アスキー）コード規格に基づく「文字コード（10進数の整数値）」です。
ASCIIコードにおいて、数字の文字（'0'〜'9'）には、以下のように連続した整数値が割り当てられています。
- 文字 `'0'` = 10進数の `48`
- 文字 `'1'` = 10進数の `49`
- 文字 `'2'` = 10進数の `50`
...
- 文字 `'9'` = 10進数の `57`

C++言語の仕様として、シングルクォーテーションで囲まれた文字（例: `'0'`）を算術演算に用いると、コンパイラはそれを対応するASCIIコードの整数値（この場合は48）として評価します。
したがって、受信した文字コードから `'0'`（48）を減算する操作は、文字コードのオフセット（48）を相殺する数学的処理を意味します。
例えば、受信した文字が `'5'`（ASCIIコード53）であった場合、内部的には `53 - 48` という演算が行われ、結果として純粋な整数値の `5` が得られます。 この論理により、任意の1桁の数字文字から、計算処理に利用可能な整数値を抽出することが可能です。

- 受信した数字は、数値ではなく文字として届きます。
- 文字の `'0'` を引くと、数字文字を計算用の数値に変換できます。

## Lesson 08: I2C通信とビット演算（SHT31センサ）

### このレッスンの目標
- I2C通信の仕組みを理解する
- `Wire` ライブラリの関数を使ってセンサと通信する
- ビット（bit）の概念と「ビットずらし」の仕組みを理解する



このLessonで使う基板上の接続：

| 信号 | XIAO RP2040 / XIAO SAMD21のピン | プログラムで使う名前 |
|---|---|---|
| SHT31のデータ線 | D4 / SDA | `Wire` のSDA |
| SHT31のクロック線 | D5 / SCL | `Wire` のSCL |
| SHT31の電源 | 3V3 | 電源として使用 |
| SHT31のGND | GND | 回路の基準 |

XIAO SAMD21でもD4がSDA、D5がSCLとして定義されています。そのため、SAMD21を使う場合もサンプルコードの `Wire.begin()` や `Wire.requestFrom()` の考え方はそのまま使えます。

### 08-1. I2C通信とは

I2C（Inter-Integrated Circuit）は、マイコンとセンサなどの間でデータのやり取りを行うための通信方式（シリアル通信の一種）です。
大きな特徴は、**たった2本の線だけで複数のデバイスと通信できる**点です。

1. **SDA (Serial Data)**：データを送受信するための線
2. **SCL (Serial Clock)**：データの送受信タイミングを合わせるための基準となるクロック（時計）の役割を果たす線

I2Cでは、マイコンが「マスター（親）」、センサが「スレーブ（子）」という役割を持ちます。
SCLとSDAの通信線には、複数のセンサを直列（バス接続）に繋ぐことができます。
たくさんセンサが繋がっていても、誰と通信するかを特定するために、各デバイスには**「I2Cアドレス（デバイスアドレス）」**という固有の出席番号が割り当てられています。
マイコンは「〇〇番のセンサ、データを送って」とアドレスを指定することで、目的のセンサとだけ通信を行います。

### 08-2. `Wire` ライブラリの関数

Arduino環境でI2C通信を行う際に使用するのが `Wire.h` ライブラリです。
今回のサンプルプログラム（`example_code_8.ino`）で使用している関数の働きは以下の通りです。

- `Wire.begin()`:
  I2C通信の準備（初期化）を行います。`setup()` の中で一度だけ呼び出します。
- `Wire.beginTransmission(アドレス)`:
  指定したアドレスを持つセンサに対して、データ送信の開始を宣言します。今回はSDT31のアドレス（`0x45`）を指定しています。
- `Wire.write(データ)`:
  宛先のセンサに送信したいデータ（コマンド）を書き込みます。今回はセンサに「測定を開始して」という命令データ（`0x24` と `0x00`）を送るために使っています。これらのコマンドの数値は、**センサーのデータシートの表8**に記載されている仕様に基づいています。
- `Wire.endTransmission()`:
  `Wire.write()` で準備したデータを実際に送信し、送信モードを終了します。
- `Wire.requestFrom(アドレス, バイト数)`:
  指定したアドレスのセンサに対して、「〇バイトのデータを返して」とデータの返送を要求します。
- `Wire.available()`:
  センサからデータが返ってきて、マイコンのメモリ（バッファ）に一時保存されているデータの数（バイト数）を返します。
- `Wire.read()`:
  受信したデータを1バイト（8ビット）ずつ読み取ります。

### 08-3. ビット（bit）とは

「ビット（bit）」とは、コンピュータが扱う情報のもっとも基本的な単位です。マイコンなどのデジタル回路では、すべてのデータは「0」か「1」（電気が流れていないか/流れているか）の2通りの状態で表現されます。この「0か1を格納する枠」の最小単位が1ビットです。

マイコンの通信では、通常**8ビット（= 1バイト）**を一つの区切りとして扱います。
8ビット集まると「00000000」から「11111111」までの256通り（10進数で0〜255）の数値を表現できるようになります。
前のセクションで紹介した `Wire.read()` で読み取れる情報のサイズも、この「8ビット（1バイト）」単位です。

### 08-4. なぜ「ビットずらし」をするのか？（データシートからの理解）

温度や湿度のデータは非常に精度が高いため、0〜255の範囲しか表現できない1バイト（8ビット）ではデータを表現しきれません。
そのため、今回使用するSDT31などの高精度なセンサは、測定値を **16ビット（2バイト分の大きさ、0〜65535）** のデータとして生成します。

しかし、I2C通信の制約上、一度にマイコンへ送受信できるデータは「8ビット（1バイト）」ずつに分割されてしまいます。
データシート(表8)を見ると、センサは16ビットの温度データを **「上位8ビット（前半）」と「下位8ビット（後半）」の2つに分割して** 送信してくる仕様になっています。

```cpp
// 受信したデータを配列に格納していく処理
Data[0] = Wire.read(); // 温度の上位8ビット
Data[1] = Wire.read(); // 温度の下位8ビット
```

このままではデータの半分ずつが別々の箱（配列）に入ったままなので、マイコン側で本来の16ビットの形に「結合」させる必要があります。
そこで登場するのが **ビットずらし（シフト演算 `<<`）** と **ビット論理和（OR演算 `|`）** です。

#### ビットシフトとOR演算によるデータの復元

サンプルコードでは以下の計算式で、本来の16ビットの温度データ（`tempRaw`）を復元しています。
```cpp
uint16_t tempRaw = (Data[0] << 8) | Data[1];
```

1. **`Data[0] << 8`（左シフト）**：
`Data[0]`（上位8ビット）の値を、左方向に8桁（8ビット分）ずらします。
（例：`00000000 10101010` を8ビット左にずらすと、`10101010 00000000` となり、右半分に8ビット分の空きスペースができます）
2. **`| Data[1]`（ビット論理和による結合）**：
ずらしてできた右半分（下位8ビット）の空きスペースに、`Data[1]`（下位8ビット）のデータをそのまま合体（OR演算）させます。

この「ずらして、足し合わせる」操作により、センサ側で2つに分割されたデータを1つの正確な16ビットデータとして復元することができます。

### 08-5. サンプルコードの全体の流れ

`example_code_8.ino` では、これまでの説明が以下のような順序で実行されています。

```cpp
// 1. センサへ測定開始のコマンド(データシート表8より、0x24と0x00)を送信
Wire.beginTransmission(SDT31_ADDR);
Wire.write(0x24);
Wire.write(0x00);
Wire.endTransmission();

delay(20); // センサの測定完了を待機（データシートの仕様）

// 2. センサに6バイト分の測定データ（温度2バイト＋湿度2バイト＋その他）を要求
Wire.requestFrom(SDT31_ADDR, 6);

// 3. データが6バイト無事に届いていれば処理を実行
if(Wire.available() == 6){
    uint8_t Data[6];
    for(uint8_t i = 0; i < 6; i ++){
        Data[i] = Wire.read(); // 1バイトずつ読み取る
    }

    // 4. 分割されたデータを「ビットずらし」で16ビットに結合
    uint16_t tempRaw = (Data[0] << 8) | Data[1]; // 温度
    uint16_t humRaw = (Data[3] << 8) | Data[4];  // 湿度

    // 5. データシートに記載された計算式に当てはめ、実際の温度(℃)と湿度(%)に換算
    float temperature = -45.0 + (175.0 * (float)tempRaw / 65535.0);
    float humidity = 100.0 * (float)humRaw / 65535.0;

    // 6. PCで確認するためシリアルモニタに出力
    Serial.print("温度: ");
    Serial.println(temperature);
    Serial.print("湿度: ");
    Serial.println(humidity);
}
```

このように、I2C通信で命令を送り、分割されて送られてきたデータを受信し、ビット演算によって復元してから計算式に当てはめるというのが、高機能なセンサを利用する際の基本的な流れとなります。

## Lesson 09: 移動平均を用いたデータの安定化

### このレッスンの目標
- 複数回のデータを取得して平均化（移動平均）し、ノイズを減らす方法を学ぶ
- 変数の宣言場所（スコープ）と初期化の重要性を理解する
- `Serial.print()` で小数点以下の表示桁数を指定する方法を知る


### 09-1. 移動平均（平均化処理）とは

センサから値を読み取るとき、電気的なノイズや環境のわずかな変動によって、値が一時的にブレることがあります。
そこで、**「複数回データを測定して合計し、その回数で割って平均を出したものを1つの測定値とする」** という手法をよく用います。これを「移動平均」や「平均化処理」と呼びます。

サンプルコード `example_code_9.ino` では、一つの測定値を出すために `for` 文を使って10回分のセンサデータを取得し、有効なデータが得られた回数（`validSamples`）で温度・湿度の合計値（`tempSum` や `humSum`）を割って平均値を出しています。

まずは全体の構造を見てみましょう。データの取得と平均値の計算は、以下のような枠組みで行われています。

```cpp
void loop() {
    // 【ステップ1】合計を入れるための箱（変数）を用意し、0.0で空にしておく
    float tempSum = 0.0;
    float humSum = 0.0;
    uint8_t validSamples = 0; // 成功した回数を数える変数

    // 【ステップ2】for文を使って、測定と合算を10回繰り返す
    for (uint8_t i = 0; i < 10; i++) {
        
        // --- センサに測定を指示してデータを読み取る処理（後述） ---
        
    }

    // 【ステップ3】ループが終わったら、合計(Sum)を回数(validSamples)で割って平均を出す
    float avgTemp = tempSum / validSamples; 
    float avgHum = humSum / validSamples;

    // ...平均値をシリアルモニタに表示する処理...
}
```

この枠組みの中で、実際にセンサからデータを読み取り、合計値の箱に足していく（ステップ2の中身）のが次の部分です。

```cpp
// センサから6バイトのデータが正しく受信できたか確認
if (Wire.available() == 6) {
    uint8_t rxData[6];
    for (uint8_t j = 0; j < 6; j++) {
        rxData[j] = Wire.read(); // 1バイトずつ配列に保存
    }

    // Lesson 08で学んだ「ビットずらし」を使って、16ビットのデータに復元
    uint16_t tempRaw = (rxData[0] << 8) | rxData[1];
    uint16_t humRaw = (rxData[3] << 8) | rxData[4];

    // データシートの計算式を使って実際の温度と湿度に変換
    float temperature = -45.0 + (175.0 * (float)tempRaw / 65535.0);
    float humidity = 100.0 * (float)humRaw / 65535.0;

    // 【重要】ここで、計算して出たばかりの「今回の温度・湿度」を合計の箱に足し込む
    tempSum += temperature; // tempSum = tempSum + temperature と同じ意味
    humSum += humidity;
    
    // 成功した回数を1増やす
    validSamples++;
}
```

この処理の流れを、プログラムの動きに合わせて順番に見ると次のようになります。

1. **(`loop` の開始)** `loop()` の先頭で `tempSum` と `humSum` を `0.0` に初期化し、合計値をためる箱を空にします。
2. **(10回ループの開始)** `for (uint8_t i = 0; i < 10; i++)` で10回測定を繰り返すループに入ります。
3. `Wire.beginTransmission()` から `Wire.endTransmission()` までで、センサに測定開始コマンド（0x24 0x00）を送ります。
4. `delay(20)` で、センサが測定を終えるまで少し待機します。
5. `Wire.requestFrom()` で6バイトのデータを要求し、`Wire.available() == 6` ならデータが正常に全部届いたと判断します。
6. `Wire.read()` を使って受信したデータを `rxData[]` という配列の箱に順番に保存します。
7. `rxData[0] << 8` のようにビットをずらして組み合わせることで、バラバラだったデータを元の16ビットの形（`tempRaw`, `humRaw`）に復元します。
8. データシートの公式（`-45.0 + ...`）を使って、`tempRaw` を人間が読める温度（℃）、`humRaw` を湿度（%）に変換します。
9. **(足し込み)** 変換した「1回分」の値を、最初に用意した `tempSum` と `humSum` という合計用の箱に足し込み（`+=` を使用）、成功した回数 `validSamples` を1増やします。
10. ここまでの手順（3〜9）を10回繰り返します。箱の中には10回分の温度と湿度が足されて大きな数値になっています。
11. **(平均の計算)** 10回のループが終わったら、`tempSum / validSamples` のように、足し合わされた合計値を成功した回数で割って平均値を求めます。
12. **(結果の表示)** 最後に `Serial.print()` を使って、求めた平均値をパソコンに表示します。

この一連の流れを見ると、移動平均の本体は「箱を空にする」→「何回も測って箱に足し込む」→「最後に回数で割る」という非常にシンプルな手順でできていることがわかります。これにより、1回の通信エラーや突発的なノイズに強くなり、より正確で安定した結果を得ることができるのです。

### 09-2. 変数の宣言場所（スコープ）と初期化の理由

サンプルコードを見ると、合計値を保存するための変数 `tempSum` や `humSum` が、ファイルの先頭（グローバル変数）ではなく、`loop()` 関数の先頭で以下のように宣言されています。

```cpp
void loop() {
  float tempSum = 0.0;
  float humSum = 0.0;
  // ... この後にfor文で10回足し合わせる ...
}
```

**なぜ、これらの変数をグローバル変数にしないのでしょうか？**

もし `tempSum` などを `loop()` の外側である全体（プログラムの先頭）でグローバル変数として宣言してしまうと、値がプログラムの動作中ずっと保持され続けてしまいます。
つまり、10回分の平均をとった後も値がリセットされず、次の測定で値がさらに蓄積されてしまい、まったく正しくない巨大な数値になってしまいます。これを防ぐには、グローバル変数の場合は毎回わざわざ `tempSum = 0.0;` とリセットする処理を書かなければなりません。

一方、`loop()` の一番最初で `float tempSum = 0.0;` と宣言（ローカル変数）しておくと、`loop()` が1周して最初に戻ってくるたびに、**自動的に変数が新しく作り直されて `0.0` に初期化** されます。
このように「リセットする必要がある一時的な集計データ」は、適切な場所のローカル変数として宣言することで、初期化忘れのバグを未然に防ぐことができます。

### 09-3. `Serial.print()` で小数点以下の桁数を指定する

計算した平均値などは小数になりますが、通常の `Serial.print()` は小数を表示する際、暗黙のうちに小数点以下2桁までを表示します。（例：`25.12`）

小数点以下の表示桁数を意図的に増やしたり減らしたりしたい場合は、第2引数として **「表示したい小数点以下の桁数」** を指定することができます。

```cpp
Serial.print(avgTemp, 3); // 小数点以下3桁まで表示（例: 25.123）
Serial.print(avgTemp, 0); // 小数点の表示を省略（例: 25）
```
この記法を使うことで、精度の高いセンサの細かい出力を確認したり、出力の表示形式を綺麗に切り詰めたりすることが可能です。

### 09-4. 演習問題



Lesson 08の知識と今回の移動平均を組み合わせて、以下の機能を持つプログラムを作成してください。

課題：
- センサに対し「周期的連続測定（周期測定モード）」のコマンドを送信して開始してください。設定は「**繰り返し精度レベル：高（High）**」「**1秒に1回測定（1.0 mps）**」となる適切なコマンドをデータシートの表から見つけて使用してください。
- データの読み出しを **10回** 実行して温度と湿度を取得し、それぞれの合計を計算してください。
- 10回読み終わった段階で、その測定結果の **平均値** を計算してください。
- 求めた平均値を、`Serial.print()` を用いて **小数点以下4桁まで** シリアルモニタに表示させてください。
- 10回測定して平均値を出すサイクルをずっと繰り返す（今回は測定中止コマンドは送らない）ように実装してください。

## Lesson 10: 関数の作成と利用（引数と返り値）

### このレッスンの目標
- データ型（int, float, voidなど）の復習をする
- 自作関数の作り方と、引数・返り値の概念を理解する
- 処理を関数化するメリットを知る

今回の新しい概念：自作関数、引数、返り値、`return`、`void`。

なぜ必要か：センサ読み取りやボタン判定の処理を関数に分けると、長いプログラムでも見通しがよくなります。

完成したらこう動く：ボタンの状態を関数で判定し、押されていない間だけセンサ値を表示します。

### 10-1. データ型の復習
関数に渡すデータや、関数から返ってくるデータを扱う上で、「型」の理解が欠かせません。ここで主要な型を復習しておきましょう。
- `int` / `uint8_t` : 整数を入れる箱です。`uint8_t` は0〜255までの正の整数のみを扱います。
- `float` : 小数を含む数値を入れる箱です。
- `bool` : `true`（真）か `false`（偽）のどちらかのみを入れる箱です。条件判定などに使います。
- `void` : 「何もない」ことを表す特別な型です。主に「値を返さない関数」の型として使われます。

### 10-2. 関数を使うメリット
これまでは、実行したい処理を `setup()` や `loop()` の中に直接すべて書いてきました。しかし、プログラムが長くなってくるとコード全体の見通しが悪くなります。
処理をまとめた「関数」を自分で新しく作る（＝**関数化**する）と、以下のような大きなメリットがあります。

1. **再利用できる**: 同じような処理を何度も書かずに、関数を1回呼び出すだけで使い回しができるようになります。
2. **見やすくなる**: メインの `loop()` の中に「操作の名前（関数名）」が並ぶことになるため、全体でどんな手順を踏んでいるのかが一目でわかるようになります。
3. **修正・管理が簡単になる**: 処理を変更したい、あるいはバグを発見したときに関数の中身を1カ所直すだけで、その関数を呼び出しているすべての場所に反映されます。

### 10-3. 引数と返り値
サンプルコード `example_code_10.ino` の中には、自分で定義した2つの関数 `LED_onoff` と `Button_push` があります。

#### 関数の基本構造
関数は次のような書き方で定義します。
```cpp
返り値の型 関数名(引数1の型 引数1の名前, 引数2の型 ...) {
    // 実行したい処理
    return 返り値;
}
```

#### プログラムの最初に関数名を書く理由（プロトタイプ宣言）

`example_code_10.ino` の先頭付近には、次のような行があります。

```cpp
void LED_onoff(uint8_t LEDPin, unsigned long delayTime);
bool Button_push(uint8_t buttonPin);
```

これは **プロトタイプ宣言** と呼ばれるものです。
関数の中身を書く前に、「このプログラムには、この名前・この引数・この返り値を持つ関数が後で出てきます」とコンパイラに知らせる役割があります。

プログラムは基本的に上から順番に読まれます。
そのため、`loop()` の中で `LED_onoff(led[i], 500);` と書いた時点で、コンパイラがまだ `LED_onoff` という関数の存在を知らないと、「その関数は何ですか？」というエラーになることがあります。

そこで、先にプロトタイプ宣言を書いておくことで、関数の本体がプログラムの下の方にあっても、`setup()` や `loop()` の中から呼び出せるようになります。
プロトタイプ宣言では処理の中身は書かず、最後にセミコロン `;` を付けます。

```cpp
void LED_onoff(uint8_t LEDPin, unsigned long delayTime); // 宣言
```

一方、実際の処理を書く部分では `{}` の中に処理を書きます。

```cpp
void LED_onoff(uint8_t LEDPin, unsigned long delayTime) {
    digitalWrite(LEDPin, HIGH);
    delay(delayTime);
    digitalWrite(LEDPin, LOW);
    delay(delayTime);
}
```

つまり、プロトタイプ宣言は「関数の予告」、下の方に書く関数本体は「実際の処理内容」だと考えると分かりやすいです。

#### 引数（ひきすう）とは
引数は、関数を呼び出すときに**「外から関数に渡すデータ」**のことです。
例えば、光らせるLEDの処理をまとめた以下の関数を見てみましょう。
```cpp
void LED_onoff(uint8_t LEDPin, unsigned long delayTime) {
    digitalWrite(LEDPin, HIGH);
    delay(delayTime);
    digitalWrite(LEDPin, LOW);
    delay(delayTime);
}
```
この `LED_onoff` 関数は、「対象となるピン番号（`LEDPin`）」と「待機時間（`delayTime`）」の2つを引数として受け取ります。
呼び出すときは、`loop()` の中で `LED_onoff(led[i], 500);` のように値を指定します。ピンや時間を変えたい場合も、引数を変えるだけで同じ関数が使い回せます。

#### 返り値（かえりち）とは
返り値は、関数での処理が終わったあと、呼び出し元に**「結果として返すデータ」**のことです。
ボタンの読み取り判定を行う以下の関数を見てみましょう。
```cpp
bool Button_push(uint8_t buttonPin) {
    if(digitalRead(buttonPin) == LOW){
        return true;
    }else{
        return false;
    }
}
```
この `Button_push` 関数は、対象のピンがLOWかどうかを調べ、押されていれば `true` を、押されていなければ `false` を「`bool` 型」として返します（`return true;` の部分です）。
結果が直接返ってくるため、`loop()` の中で `if(Button_push(button))` のように、`if`文の条件として関数の結果をそのまま扱うことができます。

一方、`LED_onoff`関数は「LEDを光らせて消す作業」をするだけで、メインの処理に報告する結果がありません。そのような場合は、返り値の型に「何もない」ことを意味する `void` を指定し、`return` 句を使いません。

### 10-4. 演習問題

演習前チェック：
- ボタン判定関数は、押されているかどうかを `bool` で返します。
- センサ読み取り関数は、表示まで行うので返り値は `void` で十分です。
- `loop()` の中は、作った関数を呼ぶだけに近い形を目指します。
関数を作る練習として、今回学んだことを活用したプログラムを作成してください。

## Lesson 11: ライブラリの利用とオブジェクトの操作

### このレッスンの目標
- ライブラリとは何か、なぜ利用するのかを理解する
- Arduino IDEでのライブラリ導入方法を知る
- ヘッダーファイル（`.h`）とソースファイル（`.cpp`）の役割と読み方を理解する
- オブジェクトの生成と「`.`（ドット）」を用いた関数の呼び出し方を習得する



このLessonで使う基板上の接続：

| 信号 | XIAO RP2040 / XIAO SAMD21のピン | プログラムで使う名前 |
|---|---|---|
| SHT31のデータ線 | D4 / SDA | ライブラリ内部で使用 |
| SHT31のクロック線 | D5 / SCL | ライブラリ内部で使用 |
| SHT31のI2Cアドレス | - | `0x45` |

XIAO SAMD21でもI2CのSDA/SCLはD4/D5です。`Adafruit_SHT31` ライブラリを使う場合も、ボード選択がSAMD21になっていればライブラリ内部で同じI2C端子が使われます。

### 11-1. ライブラリとは？なぜ使うのか

Lesson 08、09、10では、センサからデータを読み出すために「I2Cで特定のコマンド（0x24など）を送る」「ビットをずらして結合する」「変換式で計算する」といった複雑な処理をすべて手書きで記述しました。
**ライブラリ**とは、このような「よく使う複雑な処理」を誰かが事前に作成し、簡単に使える形にパッケージ化した「便利ツールの詰め合わせ」です。

**ライブラリを使う主な理由：**
1. **時間が節約できる**: ゼロからデータシートを読み解いてコマンドを実装しなくても、すぐにセンサを動かすことができます。
2. **バグが減る**: 多くの人が使ってテストされたプログラムなので、自分で書くよりもミスが少なくなります。
3. **コードが短く読みやすくなる**: 複雑な処理が裏側に隠れるため、メインのプログラム（`loop()`の中など）がすっきりとわかりやすくなります。

### 11-2. Arduino IDEでのライブラリ導入方法

ライブラリを利用するには、まず自分の開発環境にそのライブラリをダウンロードしてくる必要があります。

1. Arduino IDEのメニューから **「スケッチ」 > 「ライブラリをインクルード」 > 「ライブラリを管理」** を開きます（または左側の本棚のアイコンをクリック）。
2. 検索窓に、使いたいライブラリの名前（今回の場合は `Adafruit SHT31` など）を入力して検索します。
3. 目的のライブラリが表示されたら「インストール」をクリックします。
4. インストールが完了したら、プログラムの先頭に `#include <Adafruit_SHT31.h>` と記述することで、ライブラリの機能が引き出せるようになります。

ライブラリの中身は多くの場合、Arduinoのインストールフォルダ内にある `libraries` フォルダ、またはユーザーのスケッチブックフォルダ内の `libraries` フォルダに格納されます。

### 11-3. プログラムを作るときの手順（ヘッダーファイルとソースファイルの確認）

ライブラリなどを用いたプログラムは、通常 **ヘッダーファイル（`.h`）** と **ソースファイル（`.cpp` または `.c`）** という2つのファイルで構成されています。

- **ヘッダーファイル（`.h`）**: そのライブラリに「どんな関数や変数が用意されているか」が書かれた**目次（一覧表）**です。
- **ソースファイル（`.cpp`）**: その関数が「具体的にどういう計算や処理をするのか」が書かれた**中身（実装）**です。

新しいライブラリを使うときは、インターネットで使い方を検索するのも良いですが、**まずヘッダーファイル（`.h`）を開いてみる習慣をつけてください。**
ヘッダーファイルを読めば、「どんな名前の関数を使えばよいか」「どんな設定項目があるか」が一目で把握でき、効率よくプログラムを作ることができます。

### 11-4. オブジェクトの生成と「.（ドット）」の役割

`example_code_11.ino` には、これまでのコードには無かった以下のような記述があります。

```cpp
Adafruit_SHT31 sht31;
```
これは **オブジェクトの生成（インスタンス化）** と呼ばれる重要な処理です。
オブジェクトに関しては後のLessonで詳しく扱うので簡単に解説すると、`Adafruit_SHT31` というのは、センサを動かすための「設計図」や「金型」のようなものです。プログラムで実際にセンサを操作するには、その設計図をもとに「実体（オブジェクト）」を作成しなければなりません。
上記のコードは、**「`Adafruit_SHT31` という設計図から、`sht31` という名前の個別の実体を作れ」** とマイコンに指示しています。

実体が作られると、`setup()` や `loop()` の中で以下のように記述されます。
```cpp
sht31.begin(SHT31_ADDR);
float temperature = sht31.readTemperature();
```
ここで登場する **`.`（ドット）** は、日本語の**「〜の」**に相当します。
- `sht31.readTemperature()` は、**「`sht31`オブジェクトの、`readTemperature()`関数を実行しろ」** という意味です。

もし、同じセンサを2個つないだ場合でも、
```cpp
Adafruit_SHT31 sht31_A;
Adafruit_SHT31 sht31_B;
```
のように別々の実体を2つ生成しておけば、`sht31_A.readTemperature()` と `sht31_B.readTemperature()` とするだけで、複雑な設定なしに2つのセンサを独立して操作できるようになります。これがオブジェクトを利用する強力なメリットです。

## Lesson 12: 条件分岐（switch文）と割り込み処理

### このレッスンの目標
- `switch` 文を用いた条件分岐を理解し、`if` 文との使い分けを学ぶ
- 割り込み処理（ハードウェア割り込み）の重要性と仕組みを理解する
- `attachInterrupt()` を用いた割り込み関数の設定と `volatile` 変数について学ぶ


### 12-1. switch文とif文の違い

これまで、条件による処理の分岐には `if` 文を使ってきました。しかし、1つの変数の値（たとえば 0, 1, 2...）によってたくさんの分岐がある場合、`if` 文を連続させると以下のようになって少し見づらくなります。

**if文で書いた場合：**
```cpp
if (Button_State == 0) {
    // 状態0の処理
} else if (Button_State == 1) {
    // 状態1の処理
} else if (Button_State == 2) {
    // 状態2の処理
}
```

これをすっきりと直感的に書けるのが **`switch` 文** です。
サンプルコード `example_code_12.ino` の `loop()` の中を見てみましょう。

**switch文で書いた場合：**
```cpp
switch (Button_State) {
    case 0:
        // Button_Stateが0のときの処理（例：3つのLEDを点灯）
        break; // ここでswitch文を抜ける
    case 1:
        // Button_Stateが1のときの処理
        break;
    case 2:
        // Button_Stateが2のときの処理
        break;
}
```

`switch` 文は、**「指定した変数の値が、どの `case` に当てはまるか」**をチェックし、一致する `case` の処理を実行します。
各 `case` の最後には必ず `break;` を書きます。もし `break;` を書き忘れると、次の `case` の処理までそのまま実行されてしまうので注意してください。

**使い分けのポイント：**
- **if文:** 「50より大きいか」「AかつBか」など、複雑な条件や範囲を指定するときに便利。
- **switch文:** 「状態が 0, 1, 2, 3 のどれか」というように、特定の変数の**決まった値ごとに処理を完全に分けたい**ときに非常に見やすく便利。状態遷移（モードの切り替え）を管理するのによく使われます。

### 12-2. 割り込み処理（Interrupt）とは

これまでは、ボタンが押されたかどうかを `loop()` の中で `digitalRead()` を使って毎回確認していました（これを「ポーリング」と呼びます）。
しかし、この方法には弱点があります。例えば `loop()` の中で `delay(500)` を実行して待機している間はプログラムが一時停止しているため、その瞬間にポチッとボタンを押されてもマイコンは気付くことができません。

そこで重要になるのが **「割り込み処理（Interrupt）」** です。
割り込みとは、**「マイコンが今どんな処理をしていても（`delay` の最中などでも）、指定したピンの状態が変化した瞬間に、メインの作業を一時停止して優先的に別の関数を割り込んで実行する機能」** のことです。

**具体的な使用例：**
- **緊急停止ボタン**：ロボットが動いている最中に危険を検知してボタンが押されたら、即座にモーターの回転を止める。
- **正確な回転数の計測（エンコーダ）**：モーターが1回転するたびに送られてくる一瞬のパルス信号を、他の処理で忙しい時でも絶対に取りこぼしなくカウントする。

一瞬の変化を決して逃してはいけない重要なセンサーやボタンの読み取りにおいて、割り込み処理は欠かせない技術です。

### 12-3. 割り込み関数の設定（サンプルコードの解説）

それでは、`example_code_12.ino` でどのように割り込みを使っているのか見ていきましょう。少し書き方が複雑ですが、決まり文句のようになっています。

#### ① `attachInterrupt` で割り込みを設定する
`setup()` の中にある以下の1行が、割り込みを設定するコードです。

```cpp
attachInterrupt(digitalPinToInterrupt(button), buttonISR, FALLING);
```
この関数には3つの引数を渡します。
1. **第1引数 `digitalPinToInterrupt(button)`**: 割り込みを監視するピンの番号を指定します。普通のピン番号（`button` つまり `D9`）を、割り込み専用の内部番号に変換するために `digitalPinToInterrupt()` という関数を挟む決まりになっています。
2. **第2引数 `buttonISR`**: 割り込みが発生したときに**呼び出して実行してほしい関数の名前**を指定します（ISRは Interrupt Service Routine＝割り込み処理ルーチン の略です）。
3. **第3引数 `FALLING`**: 割り込みが発生する**タイミング（条件）**を指定します。
   - `FALLING`: ピンの電圧が HIGH から LOW に落ちた瞬間（ボタンが押された瞬間等）。
   - `RISING`: LOW から HIGH に上がった瞬間。
   - `CHANGE`: 電圧が変わった瞬間（上がったときも落ちたときも）。

XIAO SAMD21でも、この教材でボタンに使っているD9は割り込み入力として使えます。応用で別のピンを割り込みに使う場合、SAMD21ではD5とD7を同時に割り込み用途で使えない制約があるため注意してください。

この関数は一見難しそうに思いますが一種の決まり文句みたいなものなので覚える必要はありません。必要になったときに調べて使えばいいです。まあ、そもそもこんな時代に関数の名前を完全に覚える必要性は一ミリもないですけどね。
#### ② 割り込みで実行される関数 `buttonISR()`
ピンの電圧が `FALLING`（HIGH→LOW）になった瞬間、どんな処理の最中であっても強制的にメインループを中断し、以下の関数が実行されます。

```cpp
void buttonISR(){
    Button_State = (Button_State + 1) % 3;
}
```
**【非常に重要な注意点：割り込み関数のルール】**
割り込みが実行されている間、マイコンが元々行っていた処理は完全にストップしてしまいます。そのため、**割り込みの関数の中では時間をかける処理（`delay()`や`Serial.print()`など）を絶対に書いてはいけません。**
割り込みの関数は、今回のように「フラグ（変数）の数字を切り替えるだけ」にして一瞬で終わらせ、実際の時間のかかる処理（LEDを光らせる、文字を表示するなど）はメインの `loop()` 側で行うのが正しい設計です。

上記の1行の処理は、「ボタンを押すたびにボタンの状態（変数）を切り替える」ための少し賢い計算式です。
- `%` は「割り算の余り」を求める記号です。
- `Button_State + 1` で現在値に「1」を足し、それを `3` で割った余りを計算して、再び `Button_State` に代入します。
- これにより、足し算が進んでも「`0` → `1` → `2` → `0` → `1`...」と、**3で割った余りなので決して3以上にならず、0〜2の3つの状態を順番に繰り返す**ようになります。

#### ③ `volatile` という特別なキーワード
プログラムの一番上で変数宣言部分を見てください。
```cpp
volatile uint8_t Button_State = 0;
```
`volatile`（ボラタイル）は、**「この変数はメインループの見えないところで（割り込みなどによって）突然書き換えられる可能性があるから、勝手に最適化・省略をしないで毎回必ずメモリから最新の値を読み書きしてね」** とマイコンに念押しするためのキーワードです。
**割り込み処理（ISR）の中で値を変更し、それを `loop()` の中でも使う変数には、必ず宣言時に `volatile` をつける**ということを鉄則として覚えておいてください。

### 12-4. フラグ（Flag）という考え方

演習問題に入る前に、プログラミングで頻繁に登場する**「フラグ（Flag）」**という考え方について少し解説しておきます。

フラグとは、文字通り「旗」のことです。スポーツの審判が赤や白の旗を上げて状況を知らせるように、プログラムの世界では**「ある条件が満たされたことや、現在のシステムの状態を覚えておくための変数」**のことを一般的にフラグと呼びます。

例えば、「ボタンが押されたか」などの状態を記録したい場合、以下のような変数を用意します。
```cpp
bool isButtonPressed = false; // フラグの準備（初期値はfalse＝旗は下りている）
```
そして、ボタンが押された瞬間にこの変数を `true` にします（旗を上げる）。メインとなる `loop()` では、「旗が上がっているか（`isButtonPressed == true` か）」をチェックして処理を実行し、不要になったら旗を下ろす（`false` に戻す）といった使い方をします。

今回のサンプルコードの `Button_State` も、立派なフラグの一つです。割り込み関数の中では「LEDをどう光らせるべきか」を記録するフラグの番号（0, 1, 2）だけを切り替えておき、実際のLEDを光らせるような時間のかかる処理は `loop()` 側でフラグの番号を見て実行する……という設計になっています。これが、マイコンプログラミングにおけるフラグの最も安全で効果的な使い方です。

### 12-5. 演習問題


割り込みの性質を利用して、処理が止まってしまわない反応の良いプログラムを作ってみましょう。

**課題:**
「3つのLEDを500ms（0.5秒）ごとに交互に点灯と消灯を繰り返させる。ただし、ボタンが押されたら、その瞬間に状態が切り替わって『3つのLEDすべてが点灯している状態』になる」というプログラムを作成してください。

**条件:**
- `attachInterrupt()` を用いた割り込み処理を使用すること。
- 割り込み処理で状態を表す変数（フラグ）を切り替え、`loop()` 内の `switch` 文でLEDの動作モード（「交互点滅モード」と「全点灯モード」など）を切り替えること。
- **注意：** 割り込み関数（ISR）の中には `delay()` を使ってはいけません。（割り込み処理中は他の機能がブロックされるため、時間がかかる処理を書くとシステムがフリーズしてしまいます。変数の値を変えるだけの「短くて瞬時に終わる処理」にするのが割り込みのルールです）

## Lesson 13: 状態遷移とフラグ

### このレッスンの目標
- `enum class`（列挙型）の基本的な使い方を知る
- フラグ（Flag）と状態遷移（ステートマシン）の概念を理解する
- 変数を用いて過去の状態を記憶し、ボタンが「離された瞬間」をとらえる方法を学ぶ
- `for` 文を使わずに、状態と回数を管理するアルゴリズムを身につける

これまでのプログラムでは、「上から下へ順番に処理を書き、必要なら `for` 文や `delay()` でその場で繰り返す」という考え方が中心でした。
しかし、マイコンのプログラムでは `loop()` が何度も繰り返し実行されるため、1回の `loop()` ですべての処理を終わらせる必要はありません。

Lesson 13 からは、`loop()` が1回実行されるたびに「今はどの状態か」を確認し、その状態に応じた処理を少しだけ行い、必要なら次の状態を変数に記録して次の `loop()` に引き継ぐ、という考え方を扱います。
つまり、プログラムを「一度に全部進める」のではなく、「何度も回る `loop()` の中で、状態を覚えながら少しずつ進める」設計に変わります。
この考え方を使うと、ボタン操作やセンサの変化に応じて、途中で動作を切り替えられるプログラムを書きやすくなります。

### 13-1. enum class（列挙型）とは
プログラムを作るとき、「待機中が0」「動作中が1」「停止中が2」などと数字で状態を管理すると、「1って何の状態だっけ？」と後から分からなくなってしまいます。
そこで便利なのが **`enum class`（列挙型）** です。

```cpp
enum class Status {
    LED1ON,
    LED2ON,
    LED3ON
};
```
このように書くと、「`Status` という新しい型」と、「その中身である `LED1ON`, `LED2ON`, `LED3ON` という名前」を作ることができます。
使うときは `Status LEDstate = Status::LED1ON;` のように記述するため、**「今はどの状態か」が人間にとって非常に読みやすくなります。**
※名前に付いている `class` という言葉（クラス）は、後々のレッスンで詳しく学びますが、ここでは「状態の名前を安全に管理するための仕組み」程度に覚えておきましょう。

### 13-2. フラグと状態遷移（ステートマシン）
プログラミングにおいて、システムが今どのモードにいるのかを管理する手法を **状態遷移（ステートマシン）** と呼びます。また、何かの出来事が起きたことを一時的に覚えておくための変数を **フラグ（Flag：旗）** と呼びます（「フラグが立つ」という言葉の語源です）。

**具体例：全自動洗濯機**
洗濯機を例に考えてみましょう。洗濯機は以下のような「状態」を順番に遷移していきます。
1. **[待機状態]** （スタートボタンが押されるのを待つ）
2. **[給水状態]** （センサーが「水が満タンになった」という**フラグ**を立てるまで水を入れ続ける）
3. **[洗濯状態]** （一定時間が経過するまで回す）
4. **[脱水状態]** 

もし状態遷移を使わずにすべてを順番に1本のコードで書くと、途中で「一時停止」ボタンを押されたときにすぐ止める対応が非常に難しくなります。

**サンプルコードでの状態遷移の流れ**
では、今回のサンプルコード `example_code_13.ino` において、具合的にどのように遷移が行われているか見てみましょう。
このプログラムでは `LEDstate` という変数が「今の状態」を記憶しており、`switch` 文を使って以下の3つの状態を順番に切り替えています。

1. **[LED1ON の状態]**：1つ目のLEDを点灯させつつ、「ボタンが離されたか」という条件を満たす（フラグが立つ）のを待ちます。条件が満たされたら、自ら `LEDstate = Status::LED2ON;` と書き換えることで、次のループからは `LED2ON` の処理に遷移します。
2. **[LED2ON の状態]**：2つ目のLEDを点灯させつつ、再度ボタンが離されるのを待ちます。条件が満たされたら、`LEDstate = Status::LED3ON;` と状態を書き換えます。
3. **[LED3ON の状態]**：3つ目のLEDを点灯させつつ、ボタンが離されるのを待ちます。離されたら、今度は最初の `LEDstate = Status::LED1ON;` へと状態を戻します。

このように、各状態（`case`）の内部で**「次の状態へ進むための条件（フラグ）」**を監視し、条件が満たされたときに状態変数を書き換えて次のステップ・別のモードへと進む、というのが状態遷移プログラミングの基本です。

### 13-3. ボタンが「離された瞬間」の判定（エッジ検出）
今回のサンプルコードで少し難しいのが、ボタンの判定処理です。

```cpp
if (previousButtonState == LOW && digitalRead(ButtonPin) == HIGH) {
    LEDstate = Status::LED2ON; // 状態を次に進める
}
//...（中略）...
previousButtonState = digitalRead(ButtonPin); // 最後に現在の状態を保存
```

Lesson 12までは「ボタンが押されているか（LOWか）」だけを見ていました。しかしその方法だと、人間が1回ポチッと押したつもりでも、マイコンの計算速度が速すぎて「何千回も押された」と判定されてしまい、状態が一瞬でどんどん進んでしまうことがあります。

これを防ぐためには、「押されている間」ではなく **「押されていた状態から、指を離した瞬間に1回だけ」** 反応するようにする必要があります。

1. `loop()` の一番最後で、**今のボタンの状態**を `previousButtonState`（過去の状態記録用変数）に保存しておきます。
2. 次の `loop()` が回ってきたとき、`previousButtonState` には**1つ前の状況**が記憶されています。
3. もし `previousButtonState == LOW`（前回は押されていた）であり、かつ `digitalRead(ButtonPin) == HIGH`（今は指が離れている）場合。
4. この2つの条件が揃ったときこそが、まさしく **「指が離れたその瞬間」** なのです。

このように、過去の状態を記憶する変数を持っておくことで、変化が起きた「瞬間（エッジ）」だけを正確に捉えることができるようになります。

### 13-4. 演習問題



**課題:**
「3つのLEDを、順番に5回ずつ点滅させる（点灯時間/消灯時間は `delay(1000)` とする）」というプログラムを作成してください。
※今回は、以前使った `for` 文による繰り返しは使用してはいけません。

**条件:**
- `enum class` と `switch` 文を用いた状態遷移（例：`LED1_BLINK`, `LED2_BLINK`, `LED3_BLINK` など）を使用すること。
- `uint8_t count = 0;` のような点灯回数を数える専用の変数を用意すること。

## Lesson 14: ノンブロッキング処理（`millis()` の活用）

### このレッスンの目標
- `delay()` 関数が持つ「ブロッキング」という弱点を理解する
- `millis()` 関数を用いた「ノンブロッキング処理」の概念を学ぶ
- 複数の処理（LEDの点滅とボタンの監視など）を同時に並行して実行する方法を習得する



### 14-1. ブロッキング処理の弱点（`example_code_14-1.ino`）

これまで、時間を待つときには `delay()` 関数を使ってきました。まずは `example_code_14-1.ino` のコードを見てみましょう。
```cpp
void loop(){
    digitalWrite(LED1, HIGH);
    delay(3000);   // ここで3秒間、マイコンは完全に停止する
    digitalWrite(LED1, LOW);
    delay(3000);   // ここでも3秒間、完全に停止する

    if(digitalRead(ButtonPin) == LOW){
        digitalWrite(LED2, HIGH);
        delay(3000);
        digitalWrite(LED2, LOW);
    }
}
```
一見すると「LED1を3秒ごとに点滅させ、ボタンが押されたらLED2も光らせる」という普通のプログラムに見えます。
しかし、実際にこれをマイコンに書き込んで動かし、**LED1が光っている最中にボタンを押してみてください。全く反応しない**はずです。

なぜなら、`delay(3000)` が実行されている3秒間、マイコンは「何もせずにただ時間を潰す」ことしかできず、他の処理（ボタンの監視など）が完全にストップ（ブロック）されてしまうからです。このように、他の処理を止めてしまう書き方を **ブロッキング処理** と呼びます。

### 14-2. ノンブロッキング処理とは（`example_code_14-2.ino`）

この「待ち時間に何もできない」という問題を解決するのが **ノンブロッキング処理** です。マイコンが時計を時々チラチラと見ながら、設定した時間が来るまでの間は他の作業（ボタンの確認など）をする、という現実世界の人間と同じような働き方をさせます。

そこで活躍するのが **`millis()`** 関数です。
`millis()` は、**「Arduinoが起動してから今まで何ミリ秒経過したか」** という現在の時間を教えてくれる時計のような関数です。

`example_code_14-2.ino` のコードを見てみましょう。
```cpp
void loop(){
    long currentTime = millis(); // 現在の時間を取得して currentTime に保存

    // 現在の時間から前回記録した時間を引いて、3000ミリ秒(3秒)経ったか確認
    if(currentTime - previousTime > 3000){
        previousTime = millis(); // また時間を測り直すために、現在の時間を記録
        LEDOnOff = !LEDOnOff;    // LEDのON/OFF状態（フラグ）を反転させる
    }

    if(LEDOnOff == true){
        digitalWrite(LED1, HIGH);
    }
    if(LEDOnOff == false){
        digitalWrite(LED1, LOW);
    }
    
    // 【重要】delayがないので、マイコンは常にここを通り、ボタンの状態を監視できる
    if(digitalRead(ButtonPin) == LOW){ 
        digitalWrite(LED2, HIGH);
    }
}
```

**ノンブロッキング処理の仕組み：**
1. `previousTime` という変数に、「前回LEDを切り替えた時刻」を記録しておきます。
2. 毎回のループで `currentTime = millis()` として「今の時刻」を見ます。
3. `今の時刻 - 前回切り替えた時刻` を計算し、「3000(3秒)」を超えていなければ、**LEDの時間を待つ処理はスキップしてさっさと次のプログラム（ボタンの確認）に進みます。**
4. もし順調にループが回って3秒以上経っていたら、中に入ってLEDの状態を反転（`!LEDOnOff`）させ、再び `previousTime` に今の時間を記録し直します。

ぜひこちらのコードもマイコンに書き込んで動かして、違いを体感してみてください。LED1が3秒ごとに点滅している最中であっても、**いつボタンを押しても即座にLED2が反応して光る**はずです。
このように `delay()` を使わずに `millis()` を使うことで、一見すると「LEDを点滅させること」と「ボタンを監視すること」の2つの処理を**同時に（並行して）行っているように見せる**技術がノンブロッキング処理です。

### 14-3. 演習問題


ノンブロッキングの技術を使って、複数のハードウェアを同時に動かすプログラムを作成しましょう。

**課題:**
「1つのLEDをノンブロッキング処理（`millis()`）を用いて3秒間隔で点滅（ON/OFFを切り替え）させながら、その裏で、温湿度センサからのデータを2秒ごとにI2C通信で取得し、パソコン（シリアルモニタ）に表示する」というプログラムを作成してください。

**条件:**
- **決して `delay()` を使用しないこと。** LEDの点滅（3秒間隔）とセンサデータの取得（2秒間隔）は、それぞれ別々の `previousTime` のようなタイマー管理用の変数を用意して、`millis()` で個別に管理すること。
- **温湿度センサからのI2Cデータ取得にはライブラリを使用すること。**（Lesson 11で学んだ知識を活かしてください）
- `loop()` の中では、例えば「LEDを点滅制御する自作関数」と「温湿度センサからデータを取得して表示する自作関数」を並べて呼び出すだけにするなど、処理を関数で分けてスッキリした構造にすることをお勧めします。
- これにより、3秒おきのLEDの切り替えと、2秒おきのセンサデータの表示という「タイミングが異なる2つの処理」が、互いに邪魔することなく（ブロッキングされず）同時に並行して動くことを確認してください。

**ヒント:**
時間を記録するための変数は、LED用（例：`previousLedTime`）と温湿度センサ用（例：`previousSensorTime`）など、**機能ごとに別々の変数を用意すること**がポイントです。1つの変数を使い回してしまうとタイミングの計算が混ざってしまい、正しく動きません。

## Lesson 15: ノンブロッキング処理と状態遷移を用いた実践プログラミング

### このレッスンの目標
- ノンブロッキング処理（`millis()`）と状態遷移（`switch`）を組み合わせた実践的な並行処理を理解する
- タイマーを利用した状態遷移の実装パターンを学ぶ
- 複数のセンサや出力デバイスを、邪魔しあうことなく同時に制御する実践的な設計を習得する



### 15-1. ノンブロッキング処理 × 状態遷移
Lesson 13では「ボタンの状態」をトリガーにして状態遷移を行う方法を学び、Lesson 14では「時間（`millis()`）」を使ってノンブロッキングに処理を行う方法を学びました。
これらを組み合わせることで、「指定した時間が経過したら、次の状態へ遷移する」という、非常に実用的なプログラムが書けるようになります。

サンプルコード `example_code_15.ino` を見てみましょう。このプログラムは、「LEDを順番に切り替える処理」と「アナログピンからセンサのデータを読み取り平均化して出力する処理」の2つを同時に（並行して）行っています。

### 15-2. サンプルコードの処理の動き

プログラムの `loop()` 内は、大きく「LEDの制御ブロック」と「センサの読み取りブロック」に分かれています。これらは `delay()` なく高速に回り続けるループの中で、交互に実行され続けます。

#### ① 時間の取得とLEDの状態遷移
まず `loop()` の先頭で `currentTime = millis();` を実行し、ループごとの正確な時刻を把握します。
次に `switch (LEDstate)` によって、LEDの点灯状態の分岐に入ります。

```cpp
case LED1ON:
    digitalWrite(led[0], HIGH); // まずLED1を点灯
    
    // 【時間の判定】前回の切り替えから3000ms（3秒）経過したか？
    if(currentTime - previousTime > 3000){  
        previousTime = millis();    // 時計の基準をリセット
        LEDstate = Status::LED2ON;  // 【状態の遷移】次の状態へ進む
    }
    break;
```
このブロックは以下のように動いています。
1. `LED1` を `HIGH` (点灯) にします。
2. 経過時間を計算します。3秒経っていなければ、`if` 文の中には入らずそのまま `break;` で `switch` 文を抜けます。（この間、マイコンはブロッキングされず下の処理へ進みます）
3. 何周も `loop()` が回るうちに3秒が経過すると、`if` 文の中に入ります。
4. `previousTime` を今の時間に更新し、次の状態 `Status::LED2ON` へ書き換えます。これにより、次のループからは `LED2ON` の `case` が実行されるようになります。

この仕組みにより、`delay(3000)` を一切使わずに「3秒待ってから次へ進む」という動作が実現されています。

#### ② 並行して動くアナログセンサの読み取り
`switch` 文を抜けると、そのままループの後半にあるセンサ処理が実行されます。

```cpp
sum += analogRead(analogPin);
samplecount++;

if(samplecount > 20){
    float cm = ((float)sum / samplecount) * 1.27; // 20回分の平均値を距離(cm)に変換
    samplecount = 0; // カウントリセット
    sum = 0;
    Serial.print("Distance :");
    Serial.print(cm);
    Serial.println("cm");
}
```
ここでは `analogRead(analogPin)` を使ってセンサから値（電圧）を読み取り、`sum` に足し込んでいます（Lesson 09で学んだ移動平均の考え方）。
そして、`samplecount` が20回を超えたタイミングで平均値をもとに距離（cm）を計算し、`Serial.print()` で表示します。

**全体の動きをまとめると:**
「常にLEDの点灯と経過時間の確認」を一瞬で行い、その直後に「センサの読み取りと20回に1回の表示」を一瞬で行う、という作業を凄まじいスピードで繰り返しています。
その結果、人間から見ると**「3秒ごとにLEDが順番に切り替わりながら、裏では絶え間なくセンサデータが計算・表示されている」**という、真にリアルタイムなマルチタスク動作が実現されるのです。

## Lesson 16: 関連するデータをまとめる「構造体（struct）」

### このレッスンの目標
- 構造体（`struct`）の仕組みや定義の方法を理解する
- なぜ構造体を使うと便利なのか（使うメリット）を理解する
- 「.（ドット）」演算子を使って構造体の中のデータにアクセスする方法を学ぶ
- 変数と構造体を活用し、ノンブロッキングな移動平均処理を実装する

### 16-1. なぜ構造体を使うのか？

プログラムが高度になり複数の複雑なデバイス（例えば、温湿度センサと超音波センサなど）を同時に扱うようになると、用意しなければならない変数が急激に増えていきます。

たとえば、Lesson 09でやったような移動平均（合計を出して回数で割る）を2つのセンサで行おうとした場合、普通に変数を宣言すると以下のようになります。
```cpp
unsigned long analogAdd = 0;
uint8_t analogValidTime = 0;
float analogAvg = 0.0;
float analogResult = 0.0;

unsigned long pwmAdd = 0;
uint8_t pwmValidTime = 0;
float pwmAvg = 0.0;
float pwmResult = 0.0;
```
これでは変数が散らかってしまい、プログラムを書いている途中で「`analogAdd` を `pwmValidTime` で割ってしまう」といった書き間違い（バグ）が起きやすくなります。

そこで活躍するのが **構造体（`struct`）** です。
構造体は、**関連する複数の変数を1つの「グループ」としてまとめる**機能です。「データの詰め合わせパック」や「オリジナルのデータ型」を自分で作る機能と言えます。

### 16-2. 構造体の仕組みと使い方（サンプルコードの解説）

サンプルコード `example_code_16.ino` を見てみましょう。

#### ① 構造体の「型（テンプレート）」を定義する
まず、プログラムの上部で「どんな変数たちをパックにするか」というテンプレートを作ります。
```cpp
struct SensorData {
    unsigned long add;      // 合計値を入れる箱
    uint8_t validTime;      // 測定回数を入れる箱
    float avg;              // 平均値を入れる箱
    float result;           // 最終結果を入れる箱
};
```
これで、`SensorData` という新しいオリジナルの「型」ができました。（※最後の中カッコの後に `;` が必要なことに注意してください）

#### ② 構造体の「実体（変数）」を作る
次に、このテンプレートを使って、実際のデータを入れる変数を作成します。
```cpp
SensorData analogDistance; // アナログピン用データのまとまり
SensorData PWMDistance;    // PWMピン用データのまとまり
```
これで「合計・回数・平均・結果」がセットになった箱を、センサの数だけコンパクトに用意できました。

#### ③ 「.（ドット）」で中身を読み書きする
構造体の中にある個別の変数（メンバ変数と呼びます）を使うときは、Lesson 11でライブラリのオブジェクトを使ったときと同じように **`.`（ドット）** でつなぎます。「〜の」という意味合いです。

```cpp
analogDistance.add += analogRead(analog_Pin); // analogDistanceのaddに足し込む
analogDistance.validTime++;                   // analogDistanceのvalidTimeを1増やす
```

このように構造体を使うことで、「誰の」データなのかが一目でわかり、センサが増えても変数がごちゃごちゃにならず、非常に整理されたプログラムを書くことができます。

## Lesson 17: クラス（Class）とオブジェクト指向の基礎

今回は、C++における非常に強力で、かつ初学者にとって少し壁になりやすい概念である「**クラス（Class）**」について学びます。

### このレッスンの目標
- クラス（`class`）を使って、データと処理をひとまとまりにする考え方を知る
- `private` と `public` の役割を理解する
- コンストラクタを使って、初期設定をまとめる方法を学ぶ
- センサ処理を再利用しやすい形に整理する


### 17-1. クラスとは？（構造体との違い）
前回の Lesson 16 で「構造体 (`struct`)」を学びました。構造体は「関連する変数をひとまとめにした箱」でした。
クラス（`class`）は、その構造体をさらに進化させ、**「変数（データ）」だけでなく、「関数（そのデータを使った処理・振る舞い）」も一緒にひとまとめにしたもの**です。

もっと簡単に言うと、クラスとは**「自分だけのオリジナルな設計図」**を作ることです。設計図の中には「どんな情報を持っているか（変数）」と、「どんな動作ができるか（関数）」が書かれています。

### 17-2. クラスの作り方と4つの重要キーワード（example_code_17.ino の解説）

サンプルコード `example_code_17.ino` を少しずつ分割しながら、クラスを使いこなすための**4つの重要キーワード**と一緒に丁寧に見ていきましょう。ここでは、センサのデータを計算するための専用のクラス `SensorCalcu` を作っています。

#### ① `private` と `public`（アクセス修飾子）
クラスの中には、外から**「隠しておく部分」**と**「公開する部分」**を分ける機能があります。

```cpp
class SensorCalcu {
    // ----------------------------------------------------
    // private（プライベート）: 外部から勝手にいじられたくない隠し変数
    // ----------------------------------------------------
    private:
        uint8_t Pin;            // ピン番号
        unsigned long add = 0;  // 測定値の合計
        uint8_t validTime = 0;  // 測定回数
        float avg = 0;          // 平均値
        float result = 0;       // 最終的な計算結果

    // ----------------------------------------------------
    // public（パブリック）: 外部から自由に呼び出せる窓口
    // ----------------------------------------------------
    public:
        // (この後に書かれる関数などは外から自由に使える)
```

- **`private`（非公開）**：外部からは一切アクセス（読み書き）できないようにする設定です。
  上記のように `add` や `validTime` などの「計算途中で使う裏方の変数」を `private` にします。こうすることで、後で `loop()` の記述中に間違って `analogDistance.add = 1000;` などのように直接書き換えられ、システムが壊れるバグを**確実に防ぐ**ことができます。「外からいじられたくないものは隠す」のがクラスの鉄則です。
  とりあえず変数は `private` 関数は `public` という理解で大丈夫です。

#### ② コンストラクタ（Constructor）
コンストラクタは、**そのクラスが生成されるときに「たった1回だけ自動で」呼ばれる特別な関数**です。必ず **クラス名と全く同じ名前** にします。（`public` の中に書きます）

```cpp
        // コンストラクタ（初期化のための特別な関数）
        SensorCalcu(uint8_t PinNumber) {
            Pin = PinNumber;         // 受け取ったピン番号を自分の変数に保存
            pinMode(Pin, INPUT);     // 自動的に INPUT に設定！
        }
```
本来、ピンのモード設定は `setup()` の中で `pinMode(D3, INPUT);` のように一つずつ書く必要があります。しかし、コンストラクタを使うことで、クラスを作った瞬間に**自動で初期設定が終わる**ようになります。「このセンサを使う時は、必ず初期設定を忘れずにやってね」という面倒な手続きを完全に自動化できます。

#### ③ クラス内の関数（メソッド）を作る
クラスの中で定義された関数のことを**メソッド**と呼びます。これも `public` に書いて、外から「計算して！」と命令できるようにします。

```cpp
        // アナログ用の読み取り・計算メソッド
        float analogCalcu(uint8_t count) {
            for(uint8_t i = 0; i < count; i++) {
                add += analogRead(Pin);   // private変数の add に足し込む
                validTime++;
                delay(50);
            }
            avg = (float)add / validTime;
            return avg;
        }

        // 変数をリセットするメソッド
        void reset() {
            add = 0;
            validTime = 0;
            avg = 0;
            result = 0;
        }
}; // クラスの終わりにはセミコロン「;」が必要
```
これらのメソッドは、自分自身の `private` 変数（`add` や `Pin` など）を自由に使って計算を行うことができます。

#### ④ インスタンス化（実体の生成）とメソッドの呼び出し
クラスはあくまで「設計図」です。設計図を持っているだけではメモリ上にデータは作られず、計算もできません。実際に使えるようにメモリ上に「実体」を作ることを**インスタンス化**と呼びます。

```cpp
// クラス名   変数名(インスタンス名)( コンストラクタへの引数 );
SensorCalcu analogDistance(analog_Pin);
SensorCalcu PWMDistance(PWM_Pin);
```
ここで `analogDistance` という実体と、`PWMDistance` という実体の2つを作りました。
この時、引数にピン番号（`analog_Pin`など）を渡しているので、**自動的にコンストラクタが動き**、それぞれ入力モードに設定されます。

作られた2つのインスタンスは**全く独立**しています。一方が計算を進めても、もう片方には一切影響しません。別々のロボットを2体作り出したようなイメージです。

そして、作ったインスタンスは、名前の後に「`.`（ドット）」をつなげることで、`public` に設定されたメソッド（関数）を呼び出すことができます。

```cpp
void loop(){
    // analogDistance というマシンの、analogCalcu という機能のスイッチ（10という設定）を押す
    float analogresult = (analogDistance.analogCalcu(10) / 147.0) * 2.54;
    float PWMresult = PWMDistance.pulseCalcu(10) * 1.27;

    // 次のループのためにリセットマシンのスイッチを押す
    analogDistance.reset();
    PWMDistance.reset();
}
```

### 17-3. 全文コードと、なぜクラスを使うのか？

ここまでの知識を踏まえて、もう一度プログラム全体を追ってみてください。非常にスッキリとした構造になっていることがわかるはずです。

クラスを使う一番のメリットは**「完全に独立した部品として再利用できること」**です。
例えば、同じ種類のセンサが急に4つに増えたとします。もしクラスを使っていないと、使用する変数と計算関数を4セット分もコピペして名前を変えて……と非常にごちゃごちゃします。
しかし、クラスを作っておけば、
```cpp
SensorCalcu sensorA(D2);
SensorCalcu sensorB(D3);
SensorCalcu sensorC(D4);
SensorCalcu sensorD(D5);
```
とたった4行宣言するだけで、それぞれの初期化も、状態を保存するメモリ管理も、計算用のメソッドの準備もすべて完了します。非常に安全で美しい、実践的なプログラムが書けるようになります。

## Lesson 18: `union` によるデータの見方の切り替え

### このレッスンの目標
- `union` の基本的な仕組みを理解する
- `struct` と `union` の違いを知る
- 1つのデータを「数値」としても「バイト列」としても見る考え方を学ぶ
- センサ値や通信データをバイナリ形式で扱うときの注意点を知る

Lesson 16 では `struct` を使って、関連する複数のデータを1つのまとまりとして扱いました。
Lesson 17 では `class` を使って、データと処理をひとまとまりにしました。

この Lesson で扱う `union` は、それらとは少し違い、**同じメモリ領域を複数の型で見られるようにする仕組み**です。
センサ値を通信で送るときや、受信したバイト列を別の型として解釈するときに登場することがあります。

### 18-1. `struct` と `union` の違い

まずは `struct` と `union` の違いを確認します。

`struct` は、メンバ変数をそれぞれ別の場所に持ちます。

```cpp
struct SampleStruct {
    uint8_t a;
    uint8_t b;
};
```

この場合、`a` と `b` は別々のデータです。
`a` に値を入れても、`b` の値は変わりません。

一方、`union` は、複数のメンバが同じメモリ領域を共有します。

```cpp
union SampleUnion {
    uint16_t value;
    uint8_t bytes[2];
};
```

この場合、`value` と `bytes` は別々のデータを持っているのではなく、**同じ場所に入っているデータを、違う形で見ている**だけです。

- `value` として見る → 16ビットの整数として見る
- `bytes[0]`, `bytes[1]` として見る → 1バイトずつ分けて見る

つまり、`struct` は「複数のデータをまとめる」ための仕組みで、`union` は「同じデータを別の形で見る」ための仕組みです。

### 18-2. メモリのアドレスとポインタにつながる考え方

`union` を理解するには、「変数はメモリ上のどこかに置かれている」という考え方が重要です。
メモリとは、プログラムが値を一時的に保存しておく場所です。
変数を作ると、マイコンはその値を保存するための場所をメモリ上に用意します。

このメモリ上の場所を表す番号のようなものを **アドレス** と呼びます。
現実世界の住所のように、「この値はメモリのこの場所に置かれている」と示すための情報です。

そして、今後 C/C++ をさらに学ぶと **ポインタ** という概念が出てきます。
ポインタは、簡単に言うと「値そのもの」ではなく「値が置かれているアドレス」を扱うための仕組みです。
たとえば、ある変数の値を直接渡すのではなく、その変数が置かれている場所を渡すことで、別の関数から同じデータを操作できるようになります。

`union` はポインタそのものではありません。
しかし、`union` は「同じメモリ上の場所にあるデータを、別の型として見る」という点で、アドレスやポインタの考え方につながっています。

たとえば、次の `union` では、`value` と `bytes` は別々の場所にあるわけではありません。

```cpp
union FloatBytes {
    float value;
    uint8_t bytes[4];
};
```

`value` として読むと、同じメモリ上のデータを `float` として解釈します。
`bytes` として読むと、同じメモリ上のデータを1バイトずつの配列として解釈します。
つまり、`union` は「同じ住所にあるものを、違う見方で読む」ための仕組みだと考えると理解しやすくなります。

この考え方は、後でポインタやバイナリ通信を学ぶときにも重要になります。
プログラムでは、値そのものだけでなく、「値がメモリ上でどのように並んでいるか」を意識する場面があるからです。

### 18-3. なぜ `union` を使うのか

マイコンでセンサやPCと通信するとき、データは多くの場合、1バイトずつ送受信されます。
しかし、実際に扱いたい値は、`int` や `float` のように複数バイトを使う型であることがあります。

たとえば、温度を `float` 型で持っている場合、プログラム上では次のような1つの値として扱います。

```cpp
float temperature = sht31.readTemperature();
```

しかし、通信で送るときには、この `float` の中身を1バイトずつ取り出したくなることがあります。
そのようなときに、`union` を使うと、同じデータを「`float` の値」としても「4個のバイト」としても扱えます。

```cpp
union FloatBytes {
    float value;
    uint8_t bytes[4];
};
```

`float` は多くのArduino環境で4バイトのデータです。
そのため、`uint8_t bytes[4]` を用意すると、`float` の中身を1バイトずつ確認できます。

### 18-4. サンプルコードの確認（example_code_18.ino）

`example_code_18.ino` では、温湿度センサ（SHT31）から温度を読み取り、その `float` の値を `union` を使って4バイトに分け、シリアルモニタに16進数で表示します。
基板上では、SHT31 のデータ線は **D4 / SDA**、クロック線は **D5 / SCL** に接続されています。

```cpp
#include <Wire.h>
#include <Adafruit_SHT31.h>

const uint8_t SHT31_ADDR = 0x45;

Adafruit_SHT31 sht31;

union FloatBytes {
    float value;
    uint8_t bytes[4];
};

FloatBytes temperature;

void setup() {
    Serial.begin(9600);
    Wire.begin();
    sht31.begin(SHT31_ADDR);
}

void loop() {
    temperature.value = sht31.readTemperature();

    Serial.print("temperature: ");
    Serial.println(temperature.value);

    for(uint8_t i = 0; i < 4; i++) {
        Serial.print("byte ");
        Serial.print(i);
        Serial.print(": 0x");
        Serial.println(temperature.bytes[i], HEX);
    }

    Serial.println();
    delay(1000);
}
```

このコードでは、まず `temperature.value = sht31.readTemperature();` によって、SHT31から読み取った温度を `union` の中に入れています。
その後、`temperature.bytes[0]` から `temperature.bytes[3]` を読み出すことで、同じデータを1バイトずつ見ています。

ここで重要なのは、`value` と `bytes` が別々のデータではないという点です。
`value` に入れた値と、`bytes` で見えている値は、同じメモリ領域を別の見方で読んだものです。

### 18-5. 16進数で表示する理由

サンプルコードでは、次のように `HEX` を指定して表示しています。

```cpp
Serial.println(temperature.bytes[i], HEX);
```

`HEX` は、数値を16進数で表示する指定です。
バイト列を確認するときは、10進数よりも16進数の方が読みやすいことが多いです。

たとえば、1バイトは `0` から `255` までの値を持てます。
これを16進数で表すと、`0x00` から `0xFF` までの2桁で表せます。
そのため、バイト単位のデータを扱うときは、16進数表記がよく使われます。

### 18-6. 注意点：バイトの並び順

`union` を使うと、同じデータを別の型として見ることができます。
ただし、バイトの並び順には注意が必要です。

たとえば、4バイトの `float` がメモリ上でどの順番に並ぶかは、マイコンや環境によって変わることがあります。
この並び順のことを **エンディアン** と呼びます。

そのため、`union` を使ってバイト列を直接通信に使う場合は、送る側と受け取る側でバイトの順番をそろえる必要があります。
この Lesson では、まず「同じデータを別の形で見られる」という考え方を理解することを目標にします。

### 18-7. 演習問題

**課題:**
`union` を使って、超音波センサから得られた距離データを `float` 型として保存し、その中身を4バイトに分解してシリアルモニタに表示するプログラムを作成してください。

今回は基板上の超音波センサ用アナログ出力を使います。

**条件:**

## Lesson 19: ポインタ渡しで関数から複数の値を受け取る

### このレッスンの目標
- 値渡しとポインタ渡しの違いを理解する
- `&` と `*` の基本的な意味を知る
- 関数の中から、呼び出し元の変数を書き換える方法を学ぶ
- SHT31から読み取った温度と湿度を、ポインタ渡しで関数から受け取る

Lesson 10 では、自分で関数を作る方法を学びました。
Lesson 18 では、変数がメモリ上に置かれていて、その場所を表す情報をアドレスと呼ぶことに触れました。

この Lesson では、その2つをつなげて、**関数に変数のアドレスを渡す**方法を扱います。
これを使うと、関数の中から呼び出し元の変数に値を書き込めるようになります。

### 19-1. 値渡しでは元の変数は変わらない

まず、普通に関数へ値を渡した場合を確認します。

```cpp
void changeValue(int value) {
    value = 100;
}

void setup() {
    Serial.begin(9600);

    int x = 10;

    changeValue(x);

    Serial.println(x);
}

void loop() {
}
```

このコードでは、`changeValue(x);` によって `x` を関数に渡しています。
しかし、シリアルモニタに表示される値は `100` ではなく `10` のままです。

これは、関数に渡された `value` が、元の `x` そのものではなく、`x` の値をコピーした別の変数だからです。
このように、値そのものをコピーして関数に渡す方法を **値渡し** と呼びます。

### 19-2. ポインタ渡しとは

元の変数を関数の中から書き換えたい場合は、値そのものではなく、変数が置かれているメモリ上の場所、つまりアドレスを渡します。
アドレスを受け取る変数が **ポインタ** です。

```cpp
void changeValue(int* valuePointer) {
    *valuePointer = 100;
}

void setup() {
    Serial.begin(9600);

    int x = 10;

    changeValue(&x);

    Serial.println(x);
}

void loop() {
}
```

このコードでは、`changeValue(&x);` と書いています。
`&x` は「`x` のアドレス」という意味です。

関数側の `int* valuePointer` は、「`int` 型の変数のアドレスを受け取るポインタ」です。
そして、`*valuePointer = 100;` は、「`valuePointer` が指している先の変数に `100` を代入する」という意味です。

そのため、この場合は関数の外にある `x` の値が `100` に変わります。

### 19-3. `&` と `*` の整理

ポインタで特につまずきやすいのが、`&` と `*` の記号です。
まずは次のように整理しておきましょう。

| 書き方 | 意味 |
|---|---|
| `&x` | 変数 `x` のアドレスを取り出す |
| `int* p` | `int` 型の変数のアドレスを入れるポインタ変数 `p` を作る |
| `*p` | ポインタ `p` が指している先の値を読む、または書き換える |

たとえば、次のコードを見てください。

```cpp
int x = 10;
int* p = &x;

*p = 20;
```

`p` には `x` のアドレスが入っています。
そのため、`*p = 20;` と書くと、`p` が指している先、つまり `x` の値が `20` に変わります。

### 19-4. 関数から複数の値を受け取りたい場面

普通の `return` では、関数から返せる値は基本的に1つです。
しかし、センサを扱うと、温度と湿度のように、同時に複数の値を受け取りたい場面があります。

SHT31では、温度と湿度を次のように別々に読み取れます。

```cpp
float temperature = sht31.readTemperature();
float humidity = sht31.readHumidity();
```

これを1つの関数にまとめたい場合、ポインタ渡しを使うと自然に書けます。

```cpp
void readSHT31(float* temperature, float* humidity) {
    *temperature = sht31.readTemperature();
    *humidity = sht31.readHumidity();
}
```

この関数は、温度と湿度の値を `return` で返しているわけではありません。
代わりに、呼び出し元から渡された変数のアドレスを使って、その変数に直接値を書き込んでいます。

呼び出す側は次のように書きます。

```cpp
float temp = 0.0;
float hum = 0.0;

readSHT31(&temp, &hum);
```

`&temp` と `&hum` によって、`temp` と `hum` のアドレスを関数に渡しています。
関数の中では、そのアドレスを使って `temp` と `hum` の中身を書き換えます。

### 19-5. サンプルコードの確認（example_code_19.ino）

`example_code_19.ino` では、SHT31から温度と湿度を読み取り、ポインタ渡しを使って `loop()` 側の変数に値を書き込みます。
基板上では、SHT31 のデータ線は **D4 / SDA**、クロック線は **D5 / SCL** に接続されています。

```cpp
#include <Wire.h>
#include <Adafruit_SHT31.h>

const uint8_t SHT31_ADDR = 0x45;

Adafruit_SHT31 sht31;

void readSHT31(float* temperature, float* humidity);

void setup() {
    Serial.begin(9600);
    Wire.begin();
    sht31.begin(SHT31_ADDR);
}

void loop() {
    float temp = 0.0;
    float hum = 0.0;

    readSHT31(&temp, &hum);

    Serial.print("temperature: ");
    Serial.println(temp);
    Serial.print("humidity: ");
    Serial.println(hum);

    delay(1000);
}

void readSHT31(float* temperature, float* humidity) {
    *temperature = sht31.readTemperature();
    *humidity = sht31.readHumidity();
}
```

`loop()` の中で用意した `temp` と `hum` は、`readSHT31()` の外側にある変数です。
しかし、`&temp` と `&hum` を渡すことで、関数の中からそれらの変数に値を書き込めます。

### 19-6. 注意点：ポインタは便利だが慎重に使う

ポインタ渡しは便利ですが、間違ったアドレスを扱うと、意図しないメモリを書き換えてしまう危険があります。
そのため、ポインタを使うときは「このポインタは何の変数を指しているのか」を常に意識する必要があります。

今回のように、関数の引数として `float* temperature` や `float* humidity` を受け取る場合は、呼び出し側で必ず `float` 型の変数のアドレスを渡します。

```cpp
float temp;
float hum;

readSHT31(&temp, &hum);
```

型が合っていること、そして関数の中で `*temperature` のように `*` を付けて代入していることを確認しましょう。
